# 编辑评分表 v1

> 2026-10-27 · 用于人工盲评，不用于自动打分
> 配套：`data/reviews/`（记录格式见其 README）、`tools/eval-loop.mjs --editorial`

## 这张表解决什么问题

流量不足时，仍然需要一个可靠的判断"这篇稿子够不够好"的机制。没有它，接通更多数据源也只是在收集信息，而不是在做决策。

**这张表不产生总分。** 六项分别记分，分开报告。把六项加权成一个数字，等于把此前明确禁止的"混合成一个 AI 分数"重新引进来。

## 三条使用规则

1. **可以填 `N/A`，并必须写理由。** 例如一篇纯数据稿可能没有"读者可采取的行动"这一项。为了凑分而给分，比缺分更糟。
2. **不参考流量、不参考文章数量、不参考模型自评。** 评分人只看稿子与来源。
3. **红线优先于分数。** 任一条可信度红线触发，该篇**不得发布**，其余项目得 3 分也不能抵消。

## 六项评分（每项 0–3）

### 1. 结论清晰且与证据匹配（`conclusion`）

| 分 | 判定依据（可观察） |
|---|---|
| **0** | 没有明确结论，或结论与文中证据方向相反 |
| **1** | 有结论，但需要读者自己从段落里拼；或结论比证据说得更满 |
| **2** | 首段给出结论，且结论不超过证据支持的范围；允许有一处措辞偏强 |
| **3** | 首段一句话说完结论；结论的每一个断言都能在正文找到对应证据；读者不必读完全文才知道文章主张什么 |

### 2. 来源可追溯、足以支撑关键事实（`sourcing`）

| 分 | 判定依据 |
|---|---|
| **0** | 关键事实（数字、法条、政策名称）无来源，或来源是新闻转述而非原始文件 |
| **1** | 有来源列表，但关键数字中有一项无法追溯到具名文件；或日期缺失 |
| **2** | 所有关键数字可追溯到具名来源，但存在一处"来源只支持部分说法" |
| **3** | 每个关键数字都有：值、单位、期间、具名来源、检索日期；文件编号（如 P.U. (A)）出现在正文；来源可直接访问 |

### 3. 机制解释合理，且区分事实与推断（`mechanism`）

| 分 | 判定依据 |
|---|---|
| **0** | 只有事件复述，没有"为什么会这样"；或把猜测写成事实 |
| **1** | 有机制解释但停留在口号（"会影响成本"），没有说明传导步骤 |
| **2** | 说清了传导链条的主要环节，但有一处推断未标注 |
| **3** | 逐步说明传导路径（谁 → 通过什么 → 谁承担）；事实、推断、情景三种语气在句子层面可区分 |

### 4. 马来西亚影响具体（`malaysia_impact`）

| 分 | 判定依据 |
|---|---|
| **0** | 没有马来西亚影响，或用"可能影响马来西亚经济"这类空话代替 |
| **1** | 提到一个受影响群体，但没有具体载体（哪个行业、哪类岗位、哪项费用） |
| **2** | 明确指出受影响群体与载体，但缺少规模或条件限定 |
| **3** | 明确指出：哪类人/企业、通过什么具体载体（价格、岗位、手续、成本）、在什么条件下成立；并说明谁不受影响 |

### 5. 不确定性与反例披露充分（`uncertainty`）

| 分 | 判定依据 |
|---|---|
| **0** | 全文没有不确定性表述，或把预测写成已发生 |
| **1** | 只有一句"仅供参考"式的免责，未指出具体哪条不确定 |
| **2** | 指出主要不确定性，但缺少"什么证据会推翻本文" |
| **3** | 分开写清：已确认什么、推断什么、什么情况下结论会错；并给出可观察的反例条件 |

### 6. 读者可据此行动（`actionability`）

| 分 | 判定依据 |
|---|---|
| **0** | 读完不知道能做什么，也不知道该继续观察什么 |
| **1** | 有笼统建议（"保持关注"），不可执行 |
| **2** | 给出可执行动作，但未说明适用条件或核对方法 |
| **3** | 给出分人群的可执行动作 + 一句"如何自行核对"（查哪份文件、看哪个数字） |

> 媒体稿、纯解释稿可把第 6 项记为 `N/A`，理由写"解释性稿件，无可执行建议"。这是允许的。

## 可信度红线（独立检查，不计入六项）

每条回答 `触发 / 未触发`，触发即 **不得发布**。

| 红线 | 触发条件 |
|---|---|
| `unsourced_key_fact` | 关键事实（数字、法条、政策）没有来源 |
| `unverifiable_number` | 重要数字无法追溯到具名文件 |
| `fabricated_interview` | 出现采访、引语、个人经历，而来源不存在 |
| `prediction_as_fact` | 预测或情景被写成已发生的事实 |
| `stale_source` | 引用的"最新"数据实际已过期，且未标注 |

触发时必须记录：哪一句、什么证据、建议如何处理（删去 / 降级为推断 / 补来源）。

## 盲评流程

1. **首次评分前不可见**：提示词版本、模型、历史流量、其他评审者的评分。
2. 评分人只拿到：正文、来源清单、以及本表。
3. 提交分数后，才揭示上述信息，允许进行差异讨论。
4. 只有真的按此流程完成的记录，才能标 `review_type: "blind"`。
5. 同一篇由两名评审者独立评分时，才计算评审者间差异；**只有一名评审者时，报告必须写"无法计算"，不得编造一致性**。

## 复评

修改后复评时，记录 `revision.before` 与 `revision.after`（分项分数）。只有同时存在前后两次真实评分的**配对**记录，才能计算分数变化；没有配对就输出"无配对记录"，不估算改善幅度。

## 禁止

- 把六项合并成一个总分或排名。
- 把点击量、文章数量、AI 自评当作编辑质量。
- 用模拟数据补足样本。
- 为不存在的评审补写记录。
