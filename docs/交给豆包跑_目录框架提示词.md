**这是我的判断失误**：我把精力放在"把每篇做扎实"，**而没有先做一个能低成本批量产出的最小版本，让你先看到东西。** 20 篇带着五道闸门，比 100 篇粗糙的更难让你判断有没有用。

## 四、提示词（这是你真正问的东西）

### 4.1 系统提示词：直接把我们自己的规范喂给豆包

**最有价值的做法不是我从头写提示词，而是把 `项目规范_英文内容站_v1.4.md` 整个作为上下文给豆包。** 它包含：

- **文章结构**（V6.1，小节顺序固定）：`AI Summary → What happened → Why now → So what → For you → The data point → FAQ → How we calculated this → The point`
- **每个小节的字数与要求**
- **五元组纪律**：每个数字必须带 **value + unit + period + source + retrieved**
- **frontmatter 字段与长度上限**：`title` ≤120、`subtitle` ≤160、`description` ≤300（**超了会让整个构建失败**）
- **成本模型库**：文章里的账必须调模型，不许即兴算术

### 4.2 单篇提示词模板（可直接复制给豆包）

```
读 项目规范_英文内容站_v1.4.md，按 V6.1 结构写一篇文章。

主题：<在这里填>
栏目：<trade-policy | platforms | supply-chain | sourcing | logistics>
目标读者：进口商 / 跨境电商卖家
stakes：priced（成本落到发票上）或 directional

硬要求：
1. frontmatter 的 title ≤120 字符、subtitle ≤160、description ≤300。超一个字符整个构建会挂。
2. figures 至少 5 条，每条必须有 value / unit / period / source / retrieved 五项。
3. sources 至少 3 条，必须是一手文件（法规、公报、海关公告），不是二手报道。
4. 正文至少有一个带金额的每件/每柜/每吨成本表。
5. 不要写"可能""也许""据说"这类模糊词，闸门会拦。
6. AI Summary 必须是 40–60 词，多一个词就拦。
7. 结尾必须有 `## How we calculated this`，把算式写出来。
8. 每个数字都要能追到来源。查不到就写"查不到"，不要编。

写完跑：node tools/qa-check.mjs <文件路径>
通过了再告诉我。
```

### 4.3 让豆包自己维护质量：把闸门也给它

**闸门是脚本，不是我的判断**，所以豆包可以跑：

```bash
node tools/qa-check.mjs --all                                  # 结构
node tools/serp-check.mjs --all --serp=file:data/serp          # 信息增量
node tools/link-check.mjs                                      # 内链
node tools/preflight.mjs                                       # 环境+构建+覆盖率
```

**这就是为什么这套东西可以交给任何模型跑**：标准写在脚本里，不在我的脑子里。

**别让豆包"自由发挥"选题**——**我们犯过一次**：差点写一篇第 12 篇已经写得更完整的文章。**选题前必须先读自己的覆盖**（`src/content/blog/` 的文件名与标题，以及 `对比内容线_选题矩阵.md` 里的候选池）。

## 五、给你的最短路径

如果你要让豆包接手，建议这样开始：

1. **把整个目录给它**（或压缩包），让它先读 `项目规范_英文内容站_v1.4.md` 和 `进度日志.md`
2. **让它跑一次 `node tools/preflight.mjs`**，确认环境对
3. **给它上面 4.2 的模板**，先写 **1 篇**，跑 `qa-check` 看能不能过
4. **过了再给 5 篇的清单**，批量跑
5. **`node tools/preflight.mjs` 全绿**就推送到 GitHub，Cloudflare Pages 自动发布
