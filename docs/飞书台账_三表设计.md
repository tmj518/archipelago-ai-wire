# 飞书多维表格：三张表的设计（可直接建表）

> 目的：让三个月后的复盘有数据可查，而不是只有"我们发了 N 篇"。
> 现状：`feishu-sync.mjs` 只写「文章维度」，`feishu-ledger.mjs` 能自动建表建字段。
> 本文件是建表规格 —— 字段名、类型、来源、判据，直接照着建，不需要再讨论。

---

## 表 1：运行日志（L1）

**粒度：** 每次运行一行。约 360 行 / 3 个月（每天 2–4 次）。

| 字段名 | 类型 | 来源 | 说明 |
|---|---|---|---|
| 运行日期 | 文本 | `report.at` → 北京时间 | `2026-10-21` |
| 时间 | 文本 | `report.at` | `07:24` |
| 路线 | 文本 | `report.route` | `script` / `agent` |
| 判决 | 文本 | `report.verdict` | `PUBLISHED` / `PUBLISHED-WITHOUT-FINISH` / `DUPLICATE-SUBJECT` / `NO-SUBJECT` / `WRITE-FAILED` / `TURN-LIMIT` / `REJECTED` / `BUILD-FAILED` |
| 耗时秒 | 数字 | 新增 `report.durationSec` | 需要在 orchestrator / agent-run 记 start/end |
| 花费美元 | 数字 | `report.usage.usd` | 保留 4 位小数 |
| 选题 | 文本 | `report.article` 或 directive 的 slug | 失败时写预期的 slug |
| 写手 | 文本 | 新增 `report.models.writer` | `Doubao-2.1-pro` / `Doubao-lite` |
| 审核 | 文本 | 新增 `report.models.reviewer` | `DeepSeek-V4-Flash` |
| 失败原因 | 文本 | `report.reasons.join("; ")` | 成功时留空 |
| GSC曝光 | 数字 | **预留**，发布 28 天后回填 | 现在留空 |
| GA4点击 | 数字 | **预留**，发布 7 天后回填 | 现在留空 |
| 是否原创 | 文本 | **预留** | 现在留空 |

**★ 判据：连续 7 天每天都有行，且失败时「失败原因」不为空。**

## 表 2：词—页映射（关键词驱动的核心）

**粒度：** 每个 query 一行，每周刷新一次快照。约 200–800 行 / 3 个月。

| 字段名 | 类型 | 来源 |
|---|---|---|
| 快照日期 | 文本 | 抓取当天 |
| 关键词 | 文本 | GSC `dimensions=[query]` |
| 有无页面 | 文本 | 匹配 `src/content/blog/*.md` 的 `target_keyword` |
| 对应slug | 文本 | 匹配到的文章；无则空 |
| 曝光 | 数字 | GSC impressions |
| 点击 | 数字 | GSC clicks |
| 位置 | 数字 | GSC position（1 位小数） |
| CTR | 数字 | GSC ctr |
| 优先级分 | 数字 | `曝光 × (1 − CTR) × 位置权重` |
| 建议动作 | 文本 | 见下表 |

**位置权重：**

```
位置 1–3   → 0.2   （已经很好，改不动）
位置 4–10  → 1.0   （主战场）
位置 11–20 → 0.6   （够得着第一页）
位置 >20   → 0.3
```

**建议动作的判定规则（写死，不靠人判断）：**

| 条件 | 动作 |
|---|---|
| 有页面、位置 4–10、CTR < 2% | **改标题** |
| 有曝光、**无页面** | **写新文章** |
| 无曝光、无页面 | **不做**（没人搜） |
| 有页面、位置 > 20、连续 3 周不动 | **放弃该方向** |

**★ 判据：能列出至少 5 个「有曝光、无页面」的词 —— 它们就是下一批文章的题目。**

## 表 3：月度快照 + 预登记判据

**粒度：** 每月一行，共 3 行。

| 字段名 | 类型 | 说明 |
|---|---|---|
| 月份 | 文本 | `2026-11` |
| 累计文章 | 数字 | |
| 当月新增 | 数字 | |
| 累计曝光 | 数字 | GSC 90 天窗口 |
| 累计点击 | 数字 | |
| 平均位置 | 数字 | |
| 累计花费 | 数字 | 运行日志求和 |
| won篇数 | 数字 | 表 4 里 verdict=won 的数量 |
| B线占比 | 数字 | B 线文章数 ÷ 总数 |
| 近似重复数 | 数字 | B 线 + 日期后缀 = true 的数量 |

### 预登记判据（在看到结果之前写死）

```
三个月后（2027-01-21）：

成功  曝光 ≥ 5,000  且  点击 ≥ 100  且  至少 5 篇进位置 1–10
及格  曝光 ≥ 2,000  且  点击 ≥ 40
失败  曝光 < 2,000  → 市场太小或赛道选错，不是模型问题
崩盘  构建失败 > 5 次  或  近似重复率 > 30%  → 提前叫停，不跑满三个月
```

**★ 这四条必须在建表时一起录入，不能等结果出来再定。**

## 表 4：28 天回测（可选，第二阶段）

| 字段名 | 类型 |
|---|---|
| slug | 文本 |
| 关键词 | 文本 |
| 位置_before / 位置_after | 数字 |
| CTR_before / CTR_after | 数字 |
| 曝光_before / 曝光_after | 数字 |
| verdict | 文本：`won` / `flat` / `lost` |
| 动作 | 文本：改标题 / 加段 / 放弃 |

**判定规则：**

```
won   位置提升 ≥ 3 位  或  CTR 翻倍
flat  变化 < 3 位且 CTR 变化 < 50%
lost  位置下降 ≥ 3 位  或  曝光下降 ≥ 30%
```

## 护栏（不是干预，是出事时叫人）

```
护栏 1  累计花费 > $30        → 飞书告警（防 Pro 重试失控）
护栏 2  单月构建失败 > 2 次   → 飞书告警（防站点长期不可用）
护栏 3  近似重复率 > 30%      → 飞书告警（防 B 线稀释站点）
```

**★ 护栏触发时通知一次，不重复轰炸。**

---

## 实施顺序（每步都有完成判据）

| 步 | 做什么 | 完成判据 |
|---|---|---|
| 1 | 建表 1，接进 `daily.yml` 的 `if: always()` | 一天跑完，表里出现 2–4 行 |
| 2 | 报告里补 `durationSec` 和 `models` | 表 1 的这两列不为空 |
| 3 | 修 GSC 属性错配 | `gsc-report --json` 能返回 ≥ 20 个页面 |
| 4 | 建表 2，每周快照 | 能看到 ≥ 5 个「有曝光无页面」的词 |
| 5 | 建表 3 + 录入预登记判据 | 第一行月度数据出现 |
| 6 | 建表 4（第二阶段） | 前 10 篇有 after 值 |

**★ 第 3 步是闸门：GSC 读不出来，表 2 到表 4 全是空的。**
