## 4. 马来西亚要改的五处

### 4.1 信息源（最容易低估）

中国那套是「11 个部委站点，GB2312 编码，抓下来能解析」。马来西亚不一样：

| 机构 | 领域 | 备注 |
|---|---|---|
| MITI / MIDA | 投资、贸易政策 | 英文版齐全 |
| JKDM（Royal Malaysian Customs） | 关税、SST、报关 | 结构散，需逐个栏目摸 |
| JTK（Labour Dept） | 雇佣、工作准证 | 马来语为主 |
| JIM（Immigration） | MM2H / EP / DE Rantau | **JS 渲染多，抓取会难** |
| SSM | 公司注册 | 表单式页面 |
| BNM | 外汇、金融 | 英文好 |
| MPOB / Bursa | 大宗商品 | 数据页 |

**风险等级：JIM 和 JKDM 是「抓不到」的高危区**，和中国的 `mohrss`（返回 0 字符）、`gab.122.gov.cn`（直接跳过）同一类问题。开工第一周就该跑 `tools/probe-sources.yml` 逐个试可达性，别等写了稿才发现抓不到。

### 4.2 受众与选题骨架

中国站的内核是「这对我的到岸成本影响多少」。马来西亚的目标读者更分散，建议先切三段：

```
在马雇主      EP/S-Pass/Work Permit 的成本、配额、合规
移居者/远程工作者  MM2H、DE Rantau、租房、税号、银行开户
进出口商       SST、AIFA、原产地规则、清关单证
```

**建议先做第二段（移居/远程）**：搜索意图明确、竞争比 B2B 小、内容形态正好是 C 线的「程序性指南」。

### 4.3 品牌与 URL

新域名 → 新 Cloudflare Pages 项目 → 新 GSC Domain 属性（DNS 验证）→ 新 GA4 属性 → 新飞书 base。

**URL 结构可以沿用** `/blog/<slug>/`、`/guide/<slug>/`、`/category/<x>/`，因为闸门和模板都按这个写的。

### 4.4 schema 枚举

`src/content.config.ts` 里的 `category`、`audience`、`information_gain`、`priority` 都是中国站的取值。马来西亚要重新定义，**并且 `tools/qa-check.mjs` 里的枚举校验必须同步改**——两处不一致会让每篇文章都被拦。

### 4.5 计算器

中国站的 20+ 个计算器（`landed-cost.mjs`、`steel-trq.mjs`、`cbam-cost.mjs`…）全部作废。马来西亚需要新的：SST 计算、EP 成本、MM2H 门槛、AIFA 税率。**但可以只先写 1–2 个**，C 线的指南不依赖计算器。

## 5. 最大的技术风险：引文校验 vs 马来语 ★★★

**这是唯一可能让整条 C 线彻底停摆的东西，必须在第 1 周就决定。**

现状的防造假机制是：

```
每个数字必须能在抓到的原文里逐字找到（whitespace 归一化后 substring 匹配）
找不到 → 丢弃这个数字
一个都留不下 → 这篇不发
```

**如果源页面是马来语、文章用英文写，模型翻译的那一刻逐字匹配就失败了**——所有数字都会被判成「无引文」，C 线每天报 `NO-SUBJECT`。

三种解法：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 只用英文源；马来语源直接跳过 | 源少一半，但闸门不用动 |
| **B** | 抓取时保存马来语原文，校验匹配原文，正文用英文 | 要改 `ground()`，多存一份原文 |
| **C** | 放宽成语义校验（模型判断引文是否支持该数字） | **防造假强度下降，不建议** |

**建议 A 起步，B 作为兜底。** 第 1 周先跑 `probe-sources`，把「有英文版 + 有数字」的源列出来，源够 5 个就开工。

## 7. 踩坑总表（旧的六条 + 新的六条）

### 7.1 旧的六条（10-20 复盘第六章，仍然成立）

| # | 坑 | 一句话 |
|---|---|---|
| 1 | 编码 | PowerShell 的 `Convert.ToBase64String(Unicode.GetBytes(...))` 会得到 UTF-16 的 base64。**直接把原始 JSON 粘进 secret** |
| 2 | 锁死 | 「必须先通过 A 才能做 B」的链条，若 A 可能永远过不了，就是死锁 |
| 3 | 缓存 | 重复调用缓存键是 `(工具, 参数)`，不看文件内容；`write_file` 后必须清缓存 |
| 4 | 格式 | 强发路径绕过闸门不等于绕过 schema；枚举错一个值整站 404 |
| 5 | 截断 | 风格问题不该拦发布，事实问题必须拦住 |
| 6 | 时区 | 幂等护栏的「今天」要按目标时区算（马来西亚 UTC+8，同中国） |

### 7.2 新的六条（10-21 → 10-26，都用事故换来的）

| # | 坑 | 事故 | 教训 |
|---|---|---|---|
| 7 | **workflow 缩进** | 加步骤时缩进少 2 格，GitHub 直接拒解析，回 `422: Workflow does not have workflow_dispatch trigger`，**整条日更静默停摆**。发生两次（10-23、10-26） | 手写的 YAML 检查器抓不到这个。改完必须看「所有 `- name:` 是否同一深度」，并真 dispatch 一次 |
| 8 | **class 不存在 ≠ 有默认样式** | guide 页面写了 `class="wrap"`，而 `.wrap` 在 CSS 里从未定义，整页贴左边不居中 | 任何 template 用了某个 class，必须 `grep` 确认它真的被定义过 |
| 9 | **飞书 token 在响应顶层** | `tenant_access_token` 不在 `data` 里 | 别对所有接口套同一个解析函数 |
| 10 | **21001 是应用级封禁** | 旧 app 每次 token 交换都 21001，重试无用 | 换 app + 换 base。卡片走 webhook 是另一条通道，压不垮 |
| 11 | **upsert 只认一个 key** | 内容台账同一 `编号` 有两行，第二行永远不更新 | 台账必须能自愈：同键多行删除 + 语料里没有的行 prune |
| 12 | **`substantiveFigures` 有假阴性** | `32 new investigations`（单位没有 rate/duty/fee 关键词）、`1个百分点`（中文单位）都被判成「非实质」 | 别把它当唯一门槛；它现在会让 7 篇文章「零实质数字」 |

**还有两条操作习惯**（不写进代码，写进手）：

```
git push 之前必须 fetch + rebase —— 自动化每天都在往 main 推
PowerShell 里写文件用 [IO.File]::WriteAllText + UTF8 无 BOM；带 [slug] 的路径要用 -LiteralPath
```
