# 跨境英文内容站 · 项目规范 v1.2
> 更新时间：2026-09-29
> 项目：China Cross-border Insider
> 技术栈：Astro + GitHub + Cloudflare Pages（无服务器）
> 定位：英文深度内容站，Google SEO + GEO，长尾打法，12个月慢生意

---

## 一、网站定位
- **目标受众**：海外中小卖家、做中国采购的老外、做TikTok/Amazon的从业者
- **内容方向**：中国跨境电商/贸易/供应链的深度解读
- **人设**：China Supply Chain Analyst，based in Shenzhen
- **语气**：犀利、直接、有态度，像跟同行聊天，不官腔
- **差异化**：不是新闻搬运，是成本测算 + 行动清单 + 真实经验

---

## 二、技术架构（v1.2 最终版）

```
内容生产（AI + 人工）
  → Markdown + Frontmatter
  → git push 到 GitHub 单仓库
  → Cloudflare Pages 自动构建部署
  → 自动提交 GSC Indexing API
  → 每周拉 GSC 数据 → 选下周选题
```

**技术选型说明：**

| 层 | 选择 | 理由 |
| :--- | :--- | :--- |
| 框架 | Astro | 静态输出，速度极快，SEO友好 |
| 仓库 | GitHub 单仓库 | 一个网站一个仓库，简单安全 |
| 部署 | Cloudflare Pages | 免费，push即部署，零配置 |
| 视频 | YouTube 嵌入 | 不占Git仓库，懒加载 |
| 图床 | Cloudflare R2 或外部图床 | 图片不进Git仓库 |
| 数据 | Google Search Console | 免费，官方数据回流 |

**不需要的东西（明确排除）：**
- ❌ 不需要 GitHub Actions（Cloudflare原生支持push自动部署）
- ❌ 不需要服务器、Docker、n8n、Dify
- ❌ 不需要把 GitHub Token 交给任何人
- ❌ 不需要复杂的 CI/CD 配置

**成本：** 域名约 $10/年，其余全部免费。

## 六、YouTube 视频嵌入规范

**技术实现：**
- 使用 `youtube-nocookie.com` 嵌入，避免Cookie追踪
- `loading="lazy"` 懒加载，不拖垮页面速度
- 16:9 响应式容器，移动端自适应

**内容策略：**
- 视频上传到 YouTube，获取 11 位 video ID
- 把 ID 填入 Markdown 的 `youtube_id` 字段
- 文章页自动在正文顶部加载视频
- 视频描述中放文章链接（带UTM参数）
- 视频不进 Git 仓库，只存 ID

**视频内容形式：**
- 30-60秒 Shorts：提炼核心观点
- 3-5分钟 横屏：深度解读
- 用剪映图文成片或数字人，降低制作成本
- 必须包含真实录屏或你的声音，避免纯AI合成

## 七、SEO + GEO 规范

### 7.1 页面 SEO
- 每篇文章独立 `<title>` 和 `<meta name="description">`
- 自动生成 `sitemap-index.xml`
- 自动生成 `rss.xml`
- 部署后自动提交 GSC Indexing API

### 7.2 GEO（生成引擎优化）
- 文章开头必须有 **AI Summary（40-60词）**，直接回答主题
- 使用 FAQ 结构（8-12个问答）
- 使用 Comparison Table
- 使用 Definition Block
- 使用 Descriptive Headings（H2/H3/H4）
- 输出 JSON-LD Schema（Article + FAQPage + BreadcrumbList + Organization）

### 7.3 封面图
- 每篇文章自动生成 Hero Image
- 尺寸 1200×630，用于社交分享
- 图片放外部图床，不进 Git 仓库

## 八、内容生产SOP

### 8.1 每篇文章必须有的"人工痕迹"

| 元素 | 要求 | 来源 |
| :--- | :--- | :--- |
| 精确数字 | 至少5个，带数值+单位+时间+来源 | 海关总署/商务部/统计局 |
| 成本测算 | 至少1个，具体到FOB价×税率×柜量 | 作者计算 |
| 第一人称经验 | "I've been tracking China's supply chain since..." | 作者提供 |
| 明确观点 | 不和事佬，要有"Don't do X. Do Y." | 作者判断 |
| 反常识点 | "Most sellers think X, but actually Y" | 作者撰写 |
| 分人群建议 | 新卖家/品牌卖家/套利卖家分别怎么办 | 作者撰写 |

### 8.2 写作模板（每篇固定结构）

1. **Hook（100字）**：抛出反常识问题
2. **What happened（400字）**：精确数字+政策原文
3. **Why now（400字）**：联系前后政策脉络（追溯2-3年）
4. **So what（500字）**：判断+成本测算+反常识点
5. **For you（400字）**：分人群建议+行动清单+时间窗口
6. **Data point（200字）**：一个关键数字收尾

目标字数：1500-2500字。

### 8.3 数据防线（v1.1新增）
- 每个数字必须实时搜索官方源
- 搜不到就标"待核实"，绝不编造
- 信源只认：海关总署/商务部/统计局/新华社/CCTV

### 8.4 英文门禁（v1.1新增）
- 按Bloomberg/FT风格写
- 禁止AI套话（"In today's fast-paced world..."）
- 禁止逐字翻译
- 最后一道润色用 Claude 或 GPT，指令："You are a senior editor at Bloomberg. Rewrite this to sound like a native English financial journalist."

### 8.5 发布前质检清单（15项）
- [ ] 至少5个精确数字（数值+单位+时间+来源）
- [ ] 至少1个成本测算（FOB×税率×柜量）
- [ ] 至少1个反常识观点
- [ ] 至少3个分人群建议
- [ ] 没有"may/might/possibly/perhaps"模糊词
- [ ] 信源都是官方
- [ ] 字数1500+
- [ ] 有明确观点
- [ ] 有第一人称经验段落
- [ ] 有具体行动清单
- [ ] 有政策时间线
- [ ] 正文无URL（只标信源名称）
- [ ] 英文地道，无中式英语
- [ ] 有about页链接和作者卡片
- [ ] 有privacy policy和disclaimer

## 十、选题系统

### 10.1 选题表字段

| 字段 | 说明 |
| :--- | :--- |
| 关键词 | 长尾词，如"TikTok Shop China seller requirements 2026" |
| 搜索意图 | 信息型/交易型/对比型 |
| 目标字数 | 1500-2500字 |
| 信源清单 | 必须用哪几个官方源 |
| 独家角度 | 这篇跟别人有什么不同 |
| 状态 | 待写/写作中/待审/已发 |

### 10.2 长尾选题来源（每周自动）
1. Google Trends 上升词
2. Reddit r/AmazonSeller、r/ecommerce 老外问什么
3. Twitter/X 跨境从业者讨论
4. "how to"、"what is"、"vs" 长尾问题
5. GSC回流数据：哪些词有曝光没点击

**不抢大词，做长尾深度。一年200篇。**

## 十四、部署流程（最终版）

```bash
# 1. 本地测试
cd china-cross-border-insider
npm install
npm run dev
# 打开 http://localhost:4321 确认效果

# 2. push 到 GitHub
git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/你的用户名/china-cross-border-insider.git
git push -u origin main

# 3. Cloudflare Pages 连仓库
# CF Dashboard → Pages → Create project → 选仓库
# Build command: npm run build
# Output directory: dist
# 点部署，2分钟上线
```

**以后每次 `git push`，Cloudflare 自动构建部署。**
