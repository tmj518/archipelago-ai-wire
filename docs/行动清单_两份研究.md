## 一、第一梯队：配置级，< 2 天，收益明确

**全部不需要动内容，不动选题，不影响现有工作流。**

### 1.1 守住"已做对"的，不重复劳动

研究确认**已经正确**的（不要动）：自引用绝对 canonical、`http→https` 301、`/path→/path/` 308、真 404、`/privacy/` 正确 noindex、robots.txt + sitemap-index、响应式设计、**零第三方脚本**、图片写死尺寸、`datePublished` 与 `revisions` 分离。

### 1.2 Cloudflare 层（改配置，不动代码）

| 动作 | 为什么 | 证据 |
| --- | --- | --- |
| **`www` → 裸域的 301** | Google 把 redirect 列为**最强** canonical 信号；官方要求 "use redirects to send traffic from the other URLs to your preferred URL" | 实测 `www` 返回 200 |
| **加 HSTS** | 官方在"确保 HTTPS 被选为 canonical"的三条做法里列了 "Implement HSTS" | 实测无 `strict-transport-security` |
| **HTML 加边缘缓存** | 现在 `max-age=0, must-revalidate` → **每次回源**，直接压 TTFB/LCP | 实测头 |

### 1.3 `BaseLayout.astro` 一处改动

**加 `max-image-preview:large`**。Google Discover 明确要求图片 "Enabled by the `max-image-preview:large` setting"。

**⚠️ 注意**：`/privacy/` 已有 `noindex, nofollow`。**要合并分支，避免出现两个 robots meta。**

### 1.4 接通订阅表单（**这是所有增长动作的前提**）

首页现在自述：

> "Signup opens your mail client. Send the message and you are on the list — **one click is not wired up yet.**"

**成本半天，但它是第一 KPI 的入口。** 需要你给 Buttondown 用户名（或换一家）。

### 1.5 sitemap 加 `lastmod`

**值取 `revisions` 最后一条，不要用构建时间**——官方原文说 Google 只在 `lastmod` "consistently and verifiably accurate" 时才用；全部同一天 = 不可验证 = 反而无效。

### 1.6 补 `dateModified`（★ 研究没发现的那条）

规范已写好逻辑（只取真实 `revisions`），**但没输出到 JSON-LD**。这与你"反日期注水"的立场是一致的，补上就是把它落地。

### 1.7 补结构化数据

| 加什么 | 加在哪 |
| --- | --- |
| `Organization`（补 `url` / `logo` / `sameAs`） | 全站 |
| `Article` 补 `author.url`（指向 `/about/#who`）+ `image` | 文章页 |
| **`BreadcrumbList`** | 全站——**这是唯一有硬性 `required` 的结构化数据**（至少 2 个 `ListItem`） |
| `WebPage` / `CollectionPage` | sources / calculator / tracker / markets / category |

**注意区分**：官方说 Article 与 Organization **"There are no required properties"**——所以缺 `image`、`logo` 是**失去机会，不是违规**。**不要为了"修错"而慌。**

## 二、第二梯队：结构性，1–2 周

### 2.1 `/figure/<slug>/` —— 每个数字一个独立 URL ★ 投入产出比最高

**这是对标研究里最有价值的一条。**

```
OWID 一篇 155 KB 文章：85 个 <a>，44 个站内，11 个指向 grapher，9 个不同图表 URL
我们：195 条 figure 记录，0 条有 URL，全部埋在正文里
```

**改成独立 URL 后，站内 URL 从 33 → 200+，而且全是数值型长尾落点**（"7208 CBAM 每吨多少钱"这类查询的天然答案页）。

**而我们的优势是**：**每条 figure 已经带五元组**（value + unit + period + named source + retrieved date）——**OWID 没有检索日期字段。** 也就是说这个结构我们已经有了，只是没给它 URL。

### 2.2 `/instrument/<slug>/` —— 文书页

把 **119 个具名来源**变成公开的文书页（`90 FR 55232`、`Regulation (EU) 2026/2108`、`Proclamation 11052`…）。

**为什么抄这个结构**：Trivium 建了 **1,177 个 `/sources/` 信源页**，**但全部在登录墙后**——实测 `/sources/nbs/` 返回的正文就是登录表单，**索引价值为零**。

> **抄它的结构，修正它的错误：我们做公开的。**

### 2.3 `citation_*` Highwire 元标签 + 许可

OWID 有 **7 个 `citation_*` 标签 + BibTeX + 归档快照**；我们 0 个。

**约 10 行**加在 `BaseLayout`：`citation_title`、`citation_author`、`citation_publication_date`、`citation_journal_title`、`citation_pdf_url`（如有）、`citation_abstract_html_url`。

**外加定一个许可**（如 CC BY 4.0）并在 `/about/` 声明——**现在全站无许可声明**。

### 2.4 `/how-we-work/` 过程页 + `/samples/`

研究的最短板判定：**"Who"（作者可信度）**。

```
现状：byline 单字母 "V"，无作者页，JSON-LD 无 author.url
Google 明确把"是否有 byline / byline 是否指向作者背景 / 作者是否可核"写成评估问题
```

**★ 关键约束：官方明文禁止伪造作者**——"Fabricating creator profiles (such as by using AI-generated headshots, made-up names, or false credentials) is a form of deception … a signal of a low-quality page"。

**所以正确解法不是造一个更丰满的假人，而是让 byline 锚到 `/about/` 里已经存在的真实背景**（Amazon FBA / TikTok Shop / Temu，消费电子与家居）。

### 2.5 补真实图片资产

**一次性解决三个问题**：`Article.image`、Google Images 入口、Discover 缩略图。

**要求**：≥1200px 宽、>300,000 px、**16:9 或 4:3 或 1:1**、**不要用通用图（如 logo）**。

## 四、不要抄的（研究明确点名）

| 不要抄 | 为什么 |
| --- | --- |
| **Trivium 的标题双关修辞** | 服务邮件打开率，**与"数字可定价"的信任冲突**，且不命中 SERP 关键词 |
| **把信源页锁进会员墙** | 索引价值归零（实测其 `/sources/nbs/` 就是登录表单） |
| **25 人团队叙事** | 不可迁移，且我们不打算装 |
| **"日更"频率本身** | **我们一篇要读原始文书 + 做算术，日更会毁掉质量。该抄"固定节奏"，不是"每日"。** |
| **OWID 的 14,000 单元规模与非营利资助模式** | 不可迁移 |
| **删掉 per-unit HTML 表格** | **反直觉发现：Trivium 长文 `<table>` = 0，OWID 那篇也是 0**（它用"可路由的图"替代表格）。**我们的表格是原创形态，不要为了模仿而删。** |

**范围纪律（这是最大的真实风险）**：

spam policies 里最贴合本站的三条：

- **scaled content abuse** — "generate many pages without adding value"
- **doorway abuse** — "substantially similar pages"
- **keyword stuffing** — 官方例子直接点名 "lists of phone numbers without substantial added value" 与 "blocks of text that list cities and regions"

> **22 篇 + 7 篇草稿的节奏是安全的；把它变成"政策库"（政策 × 品类 × 国家）就会命中。**

**而 QRG 的一句话是对"翻译/整理官方文件"型站点的直接警告**：

> "Attribution or giving credit to other sources **doesn't replace the need for original effort**."

## 六、一个需要你决定的取舍（不是错误）

**规范 §4.3 规定正文不放 URL、来源只用机构名。全站实测对外链接 = 0。**

**而 Google 官方在 `links-crawlable` 明确说**：

> "using external links can help establish trustworthiness (for example, **citing your sources**)"

**当前做法在防抄上有理由**（竞品可以直接顺着链接抄走我们的信源链），**但确实放弃了 Google 点名的那个信任信号**。

**三种折中方案**（我不替你决定）：

| 方案 | 做法 |
| --- | --- |
| **A. 保持现状** | 正文零 URL。防抄最强，放弃信任信号 |
| **B. 只给"一次文献"链接** | 正文仍不放，但每篇底部的 sources 列表变成可点链接（`90 FR 55232` 直接链到 FR 原文）。**这是我认为的最优解** |
| **C. 正文也放** | 最贴 Google 建议，但把信源链完全交给竞品 |

**我建议 B**：**它同时满足"不给正文塞 URL"和"让读者能核验"**，而且**它把"我们读了原文"从声称变成可验证的事实**。
