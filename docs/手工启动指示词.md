```

【第零步：三条硬规则——比闸门更严，因为它们挡的是"假"] 

规则 A：表格数据必须按表格解析。
  从 HTML 取结构化数据（费用表、税率表、统计表）时，先按 <tr>/<td> 解析单元，再取值。
  剥标签后的纯文本只用于人读和关键词搜索，绝不用于取数字。
  判别信号（出现任一条就说明你在错的路上）：
    · 数字里出现孤立的小整数（9 / 11 / 12）紧挨着真正的大数字 → 那是脚注编号
    · 同一字段在两个年份读出来一模一样 → 你读到的是标签不是值
    · 某个字段的变化幅度远超通胀（比如 3.6 倍，而年调是 3%）→ 先怀疑解析，再怀疑世界
  ★ 2026-10-09 实例：`9 34` 我读成 $9.34，推出"涨了 3.7 倍"。真相是 9 为脚注、值 34.58，
    三年为 32.71 → 33.58 → 34.58，全是常规通胀。这条已写进 经验与踩坑记录.md 第四节规则 5。

规则 B：每个数字都要交叉核对到第二份文件。
  一个数字只有一个来源时，你无法区分"数字是真的"和"你读错了"。
  ★ 做法：读到的费率/税率/日期，去上一年度的同类公告、或规则本体（如 eCFR / 19 CFR）核一遍。
  ★ 做不到交叉核对时，在 How confident 里明说"单一来源，未交叉核验"。

规则 C：不许把推断写成事实，也不许编造数字。
  非事实论断标【推断】或【观点】。

  ★ 报告里的每个数字，都要能指回一个文件或一次命令的输出。

不要读：docs/archive/ 里的一切（已废弃）、README.md（不是规则）、_research/（按需查）

【第二步：确认环境】

看除「astro build」「git remote」「python」之外的项（那三项有时是沙箱产物）。

daily automation 若红，那是真问题，写进报告。
```
