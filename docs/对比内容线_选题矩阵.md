# 对比内容线选题矩阵（待办 20 的输入）

> 这份是**候选池**，不是选题清单。**每个候选都标了"依据是否已在手"**——因为核实成本是最贵的资源，而对比文的成本是两倍。

---

## 一、为什么要先做这个，而不是先找竞品

**本项目已经犯过一次同类错误（记录为 C11）**：我差点提议写一篇"欧盟 Union 处理费"的文章，**而第 12 篇已经覆盖得更完整**。

> **教训：选题先读自己的覆盖，再找竞品。**
> `serp-check` 只能证明"我们比竞品强"，**不能证明"我们没写过"**。

**对比文的成本结构更极端**：

| | 普通文章 | 对比文 |
| --- | --- | --- |
| 需要核实的对象 | 1 个 | **2 个** |
| 需要算的账 | 1 笔 | **2 笔 + 一笔比较** |
| 来源要求 | 各自一手 | **两边都要一手** |

**所以候选池的第一判据不是"有没有人搜"，而是"依据是否已在手"。**

## 四、C 类：需要全新研究（不建议现在做）

**这类是"看起来很像对比"但两边都需要从头核实的方向**：

| 方向 | 为什么贵 |
| --- | --- |
| 中国 vs 越南/印度/墨西哥 原产地对比 | **每个国家一套法律文本**，且原产地规则本身是一整个体系（RCEP/ACFTA/USMCA 各自不同） |
| 海运 vs 中欧班列 vs 空运 综合成本 | 三种运费各有报价体系，且**没有公开的一手运价**（我们的运费数据来自指数，不是报价） |
| 不同 HS 归类方案的成本差 | **归类是法律裁决，不是计算**——我们的模型算不了它 |
| 跟单信用证 vs 电汇 vs 赊销 的资金成本 | **属金融成本，不是贸易政策**，超出我们的信息源范围 |

> **C 类不是不做，是要单独立项。** 每一条的成本都相当于 1-2 篇完整文章，而**收益不确定**。

## 五、栏目分布（说明为什么现在该做对比线）

```
已发布 14 篇的栏目分布：

trade-policy    5  #####
sourcing        3  ###
logistics       2  ##
supply-chain    2  ##
platforms       2  ##
```

**三个最薄的栏目各只有 2 篇。** 而对比文有一个结构性优势：**它可以被归入任意栏目**——"美国 vs 欧盟逐件收费"进 `platforms`，"CBAM vs 配额"进 `trade-policy`。

**所以对比线同时解决两个问题**：增加内容量 + **按需填补最薄的栏目**。

## 七、这份矩阵**没有**做的事（诚实说明）

1. **没有做关键词需求验证**——我们**没有可用的搜索量数据**（`keyword-miner` 的 HTTPS 通路是坏的，`BING_API_KEY` 和 GSC 凭据都未配置）。
   **所以这份排序依据的是"依据是否在手"和"栏目是否需要"，不是"有多少人搜"。**
2. **没有做竞品覆盖对比**——`serp-check` 是对单篇做的，**不是对选题池做的**。
3. **没有决定写哪一篇**——那是你的决定。

> **要补上 1 和 2，需要先修 `keyword-miner` 的网络通路，或者配 GSC 凭据。** 那是另一件事。
