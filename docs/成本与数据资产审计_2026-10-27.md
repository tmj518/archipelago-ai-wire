### 单篇成本：**不可计算**

日志里**没有 `article_id`、`slug` 或 `run_id`**（实测字段清单里不存在）。因此无法把任何一行归因到某一篇已发布文章。

工具明确输出：

```
PER-ARTICLE COST
  not_computable: the log carries no article_id, slug or run_id, so no row can be attributed to a published piece
```

**禁止**用「总成本 ÷ 文章数」来伪造单篇成本——那是把不可归因的数字除以一个无关的分母。要得到单篇成本，必须先让 `lib-llm` 在每次调用时带上 run 标识。

## 二、GSC 数据资产：**零真实数据**

`data/gsc/` 实测：

| 项 | 值 |
|---|---|
| 文件数 | **26** |
| 类型 | `.log` **13** + `.failed` **13** |

| 日期范围 | 2026-10-02 .. 2026-10-26 |
| 总大小 | 65,005 字节 |

### 所有 13 次运行都失败

| 失败原因 | 次数 |
|---|---|
| `GSC not configured. Set GSC_CREDENTIALS and GSC_SITE_URL in .env.keywords` | 12 |
| `GSC query by page failed: error:1E08010C:DECODER routines::unsupported` | 1 |

### 更关键：这些是**上一个项目**的产物

日志中记录的输出路径是：

```
<user-profile>\Desktop\出淘官网更新工作流\data\gsc\report_20261026.failed
```

并且日志写着 `49 published articles` —— 本项目只有 **1 篇**。

**结论：`data/gsc` 不是本项目的采集结果，是旧项目遗留在工作目录里的失败记录。** 本项目自建立以来，**从未成功获取过一条 GSC 数据**。

这修正了我此前两份报告中的说法（第 1 轮"部分真实采集"、第 32 轮"部分存在"）——按证据应为：**未实现，仅有失败证据**。

### 最小数据契约（若将来接通）

将来任何写入 `data/gsc/` 的采集器必须满足：

| 字段 | 含义 | 规则 |
|---|---|---|
| `site` | GSC 属性 | 必须与 `GSC_SITE` 一致；旧项目的属性不得复用 |
| `query` / `page` | 查询维度 | 至少保留 query 与 page 两者之一，不能只存合计 |
| `clicks`, `impressions`, `ctr`, `position` | 指标 | 缺失写 `null`，**不写 0** |
| `window` | 时间窗口 | `d7`/`d28`/自定义，必须与 `captured_at` 一起存 |
| `captured_at` | 抓取日期 | ISO 日期；与数据日期区分（GSC 有 T+2 延迟） |
| `source` | `gsc` | 固定值，便于与未来的 Bing/CF 数据区分 |
| `provenance` | `observed` / `simulated` | 模拟数据永不进入指标 |
| `run_id` | 采集批次的幂等键 | 同一 `run_id` 重跑覆盖而非追加 |

并且：**存在文件 ≠ API 已授权 ≠ 定时回流已运行**。当前三者皆为否。
