# 审核协议 L1–L5（audit_protocol.md）

> **这份文件是审核的规则本体。** 可执行实现在 `tools/audit.mjs`——**以能跑的脚本为准**，
> 本文与脚本冲突时改本文。
>
> **建立于 2026-10-12。** 它取代并细化了此前的表述："三道闸门（取代全部人工审稿）"。
> 那次表述是错的两次：**闸门已增至七道**，而"取代人工"也不准确——
> **有两层（L3 的未核对标注、L5 的风险）需要判断，判断的结论要留痕，不能默认通过。**

---

## 为什么要有 L1–L5 而不是"多跑几个检查"

**因为不同层的失败方式不同，而混在一起会掩盖"哪一层没过"。**

```
L1 是机械的     —— 格式、字数、内链。失败原因永远明确，修法是确定的。
L2 是记录性的   —— 数字有没有指回一份真实文件。失败说明【文献工作没做完】。
L3 是证据强度的 —— 一个数字只有一份来源时，无法区分"是真的"和"读错了"。
                   这一层不能自动判定"对"，只能强制【标注】。
L4 是一致性的   —— 论断与来源是否自洽；有无编造的经历与面板。
L5 是判断性的   —— 政治、法律、声誉。这一层【故意不追求自动通过】：
                   不确定就写 alert，交给人。默认是"不确定"。
```

**★ 最关键的一条设计：L1、L2、L4 可以自动判"过"，L3 只能判"标注了没有"，L5 默认判"不确定"。**
**所以"全自动发布"的成立条件是 L1+L2+L4 全过、L3 全部标注、且 L5 明确 pass。**
**任何一层没结论，就走 alert。**

## L1 闸门（机械）

**判据**：`node tools/gate.mjs` → `RESULT: every gate passed`（7/7）

```
1  structural gates        结构、字数档位、V6.2 必需节
2  reviewer agent          审核器五类（A 无支撑数字 · B 摘要脱节 · C Data point 无据
                           · D 时序矛盾 · E 流程声明无据）
3  internal links          内链与孤页
4  information gain        信息增量声明可证伪
5  structured data         JSON-LD
6  content security policy CSP
7  mobile layout           320 / 390 无横向滚动
```

**失败**：拒绝发布，`alert-` 写明是哪一道。
**退出码**：非 0 即 L1 未过。

## L2 事实核对（记录性）

**每个 figure 必须满足三项，逐条机器判定：**

| # | 判据 | 怎么判 |
| --- | --- | --- |
| 1 | **指回真实文件** | `figures[].source` 非空，且**与 `src/data/instruments.json` 里某份文书的 `source` 匹配**（归一化后前缀匹配）。不匹配 → 该数字是"我们的算术"（如 `Landed Math … model`）或**来源不在已核实文书库中**，两种都要在报告里分开列 |
| 2 | **来源具名** | source 必须含机构名，不能是"业内人士"、"据报"、"某公告" |
| 3 | **日期可查** | `retrieved` 必须是 `YYYY-MM-DD` 且不晚于今天；`period` 非空 |

**★ 为什么"不匹配"不直接判失败**：本站有两类数字——
**外部文书的数字**（必须匹配）与**我们模型算出来的数字**（如 `$88.77`、`14.8 bp`）。
后者不该匹配任何文书。**所以 L2 把它们分开列：外部数字不匹配 = 警报；模型数字 = 正常，但必须自报模型名。**

## L3 交叉验证（证据强度）

**判据**：**一个关键数字只有一份来源时，必须标注"单一来源，未交叉核验"。**

```
可自动判的：文章里有没有这条标注
不可自动判的：一个数字【应该】被交叉核对而作者没做
```

**做法**：L3 报告文章里**每个来源只出现一次的数字**（单来源数字）的数量，
并检查 `## How confident` 的 `Inferred.` 段落里有没有对单来源的明示。

**★ 这一层不判"对错"，只判"诚实"**——这正是规则 B 的可执行形态：
"做不到交叉核对时，在 How confident 里明说"。

## L4 逻辑一致性（一致性）

| 判据 | 机器形态 |
| --- | --- |
| 结论由数据推出 | `reviewer-check` 的 A/B/C 类必须为 0 |
| **无编造经历** | 不得出现第一人称经营叙述：`I moved/bought/paid`、`my inventory/supplier/margin`、`our panel/data/sample` |
| **无假面板** | 不得出现 `ILLUSTRATIVE`、`placeholder figure`、`no real panel`、`SAMPLE POST` |
| 无稻草人反常识点 | `reviewer-check` E 类为 0 |

## L5 风险审核（判断性）

**★ 这一层默认"不确定"，不是默认"通过"。**

扫描四类触发词，任一命中即**不自动发布**，写 `alert-`：

| 类 | 触发 |
| --- | --- |
| 政治 | 对中国/他国政治体制的评价性表述；涉台、涉港、涉疆、涉藏的**政治**表述（商业通关事实不算） |
| 法律 | 明确的法律意见式断言（"你必须"、"这是合法的"）；对他国制裁合规的结论性建议 |
| 声誉 | 指名指控某公司违法/欺诈/造假；未公开的个体或客户信息 |
| 承诺 | 收益率、投资回报、保证结果类表述 |

**pass 的唯一形态**：上述四类**零命中**，且 `reviewer-check` 的 must-fix 为 0。
**不确定 = alert，不是 = pass。**

## L5 之二：蓝海 / 红海评估（2026-10-16 新增，来自总监指令 v5.1）

**每个选题进入 L5 时必须评分。判定规则（总监定）：**

```
总分 ≥ 40   蓝海，优先做
总分 30–39  可做，但需标注风险
总分 < 30   红海，退回重选
```

**执行**：`node tools/blue-ocean.mjs <slug>`（或 `--all`）。数据来自 `data/serp/<slug>.json`。

### ★ 10 个指标做了映射，而不是照搬——理由要能驳回

**总监给的 10 个指标是亚马逊选品的维度**：头部平均评论数、前 10 名品牌集中度、新品进入前 100 频次、价格带表现。
**来源是 Sorftime，它的蓝海原话是"潜在的蓝海品类"——那是在说"卖什么类目"。**

```
实测（2026-10-16）sorftime.com 首页：中文，亚马逊/沃尔玛/虾皮/TEMU/TikTok Shop 选品软件
  它的"蓝海/红海"用法 = 选品类 · 类目竞争度 · 品牌销量分布 · 价格策略
  10 个指标里 9 个需要【商品 listing】：评论挂在商品页、品牌集中度要有品牌在卖货、价格带要有价格
```

**本站一个都没有。** 本站发布文章，客户是进口商不是消费者。**所以按"编辑选题"做了等价映射，每个映射都在输出里具名：**

| 总监的指标 | 本站等价物 | 怎么算 |
| --- | --- | --- |
| 供需指数 | 竞品供给 vs 独立需求 | SERP 快照里的竞品页数 |
| 头部平均评论数 | **领头页面有几个带金额** | 快照 title/snippet 里含金额的比例 |
| 前 10 名品牌集中度 | 排名域名集中度 | 最大单域名占排名的比例 |
| 新品进入前 100 频次 | 编辑新鲜度 | 快照里出现的最新年份 |
| 价格带表现 | **能不能撑起成本模型** | 文章有没有 ≥3 行含金额的表 + figures 数 |
| 差异化空间 | 信息增量类型 | `information_gain` 字段 |
| 需求侧信号 | 查询是否带金额/日期意图 | `_keyword` 里的词 |
| 竞争密度 | 有效不同域名数 | 去重后的域名数 |
| 内容热度领先度 | 比有日期的竞品领先多少 | 快照 `_captured` 距今天数 |
| 品牌集中度 | 是否一个发布方占住主题 | 非官方发布方数量 |

### ★ 覆盖率是独立的门槛（这是本工具第一版的缺陷）

```
第一版：两篇没有 SERP 快照的文章算出 【50/50 → BLUE】
        因为只有 2 个指标可算，而我把它缩放成了 10 个的样子
        → 那是【制造出来的信心】，正是这一整条审核线要防的东西

修法：可算指标 < 6 个 → 判定 INSUFFICIENT-DATA，【不下结论】
      没有快照就没有竞争可言，而"没有话说"是正确的输出
```

### ★ 判别力必须被证明（规则 4 的形态）

**一个从不判红海的评分器没有判别力。** 所以本工具带一个人为校准样本：

```
data/serp/_calibration-red.json   12 个竞品页 · 7 个同一域名 · 每条 snippet 都带金额 · 快照陈旧
node tools/blue-ocean.mjs _calibration-red --file --serp=data/serp/_calibration-red.json
→ 24/50 RED（80% 覆盖率）· 退出码 1
```

**★ 全量实测（2026-10-16，31 篇）：16 蓝海 · 7 可做 · 0 红海 · 13 无快照 withheld。**
**"0 红海"配合上面那个校准样本才成立**——否则无法区分"本站选题都好"和"评分器只会给高分"。

**这一层不阻塞发布**：它是选题判据，用在选题阶段；已发布文章评分只作复盘。

## 判定与发布

```
L1 过  ∧  L2 无"外部数字来源不匹配"  ∧  L3 已标注单来源  ∧  L4 零命中  ∧  L5 零命中
  → AUTO-PUBLISH OK

否则
  → logs/alert-<stamp>.txt（写明哪一层、哪一条、原文）
  → 不发布，等处理
```

**实时执行**：`node tools/audit.mjs <article.md>` 或 `node tools/audit.mjs --drafts`

**接进流程**：

```
preflight.mjs   每次无人值守都跑「审计 + 反向证明」
                29/29 已发布通过 AND 0/5 草稿通过 → ok
                ★ 两个断言一起才成立：只跑"已发布通过"验不出工具坏了
run-daily.ps1   step 4a  七道闸门
                step 4b  L1–L5 审计   ← 未过则拒绝 push，写 alert-audit-
                step 4c  写发布清单
```

## ★ P2 设计：`evidence` 字段与核查闸门（2026-10-16 起草，**未实施**）

> **状态：P1 先跑通，本设计等 P1 上线后再实施（总监 v6.1 定案）。**
> **本文只写设计，`tools/` 里没有对应脚本，闸门里没有这一条。**

### 一、它要解决的那一个问题

**L1–L5 全部是"读执行器写出来的东西"。它们看不到原始文件。**

```
执行器写：  value: "17.45%"   source: "越南工贸部决定 2652/QD-BCT"
L2 看到：来源非空、不匿名、日期合法、在文书库里  →  过
L4 看到：没有编造标记                          →  过
L5 看到：论断与数字自洽、算术对、无风险词        →  过
★ 而 17.45% 若是读错的、或整段是编的，【没有任何一层有依据发现】
```

**这是信息问题，不是模型能力问题：审核者手上没有原件，就无法核对原件。**

### 二、设计

**给每个 figure 增加第六个字段 `evidence`：从原文里逐字摘出的那一句或那一行。**

```yaml
figures:
  - value: "17.45%"
    unit: "the highest anti-dumping duty on Chinese polyester filament yarn, as a share of CIF value"
    period: "applies to the catch-all category for all producers and exporters not named in the annex"
    source: "越南工贸部决定 2652/QD-BCT 附件"
    retrieved: "2026-10-16"
    evidence: "其他生产商 / 出口商 | 17.45%"            # ← 新增：原文里逐字存在的片段
    evidence_from: "data/sources/2026-10-16/vietnam-polyester-decision-gsgu0.html"   # ← 新增：存档文件
```

**闸门 `check-evidence.mjs`（P2 写）做三件事：**

```
1. 每个 external figure 必须有 evidence 与 evidence_from
2. 打开 evidence_from 那个存档文件，去掉标签后搜索 evidence 字符串
   · 找到 → 过
   · 找不到 → BLOCK，并打印"存档里最接近的 200 字符"，方便人判断是摘录写错还是数字编的
3. evidence_from 指向的文件必须存在，且 sha256 与 store-source 的 manifest 一致
   （★ 这一条防的是"事后补一个假存档"）
```

### 三、为什么它能挡住 L1–L5 挡不住的那一类

```
编造一个数字，现在只需要编一个来源名（一个字符串）
编造一个数字，届时需要：
  ① 编一个数字
  ② 编一段【在原文里逐字存在】的摘录 —— 而那等于真的去读了那份文件
  ③ 让那段摘录出现在一个 sha256 对得上的存档里
★ 三件事同时做到，与"我真的读了原件"是同一件事
```

**★ 而它的成本是零**：不调模型，纯字符串查找，毫秒级。

### 四、它挡不住什么（必须写明，否则会给人虚假的安心）

```
✗ 原件本身写错了 —— 我们只能保证"我们如实引用了它"
✗ 摘录取自文档的 A 处，数字却取自 B 处 —— 需要 evidence 与 value 同时出现才算强校验
   ★ 所以 P2 的判据应升级为"evidence 字符串里包含该 value"
✗ 数字读错（规则 A 那类：9 34 读成 $9.34）—— 除非摘录恰好包含脚注与值的边界
   ★ 缓解：evidence 要求【整行】而不是片段
```

### 五、实施顺序（P2 开工时按此做）

```
1. 写 tools/check-evidence.mjs
2. ★ 先证明它会失败：造一条 evidence 在存档里不存在的记录，必须 BLOCK
3. 再证明它不误杀：拿 #31 那 14 个 figure 回填 evidence，必须全过
   （#31 的存档已在 data/sources/2026-10-16/vietnam-polyester-decision-*.html）
4. 回填既有 31 篇（可分批；未回填的标为"未回填"而不是"未通过"，否则会误判旧文）
5. 接进 gate.mjs 作为第八道闸门
```

**★ 第 2 步是这个设计的核心。** 一个从不失败的核查器没有判别力——这条纪律在
`tools/blue-ocean.mjs` 的校准样本上已经用过一次，P2 沿用同一种做法。

## 建立这个协议时我自己犯的四个错（留痕）

**因为每一个都是"看起来对"的错，不记下来就会重犯。**

| # | 错 | 真相 |
| --- | --- | --- |
| 1 | L2 判"来源不在文书库 = 失败" → **20/29 已发布文章被判失败** | **文书库按设计只收录"供出 ≥2 个数字"的文书**（否则是一页一个数字的薄页）。**20 篇引用的是真实但未收录的文书。判大多数正确工作为失败，不是严格，是坏了。** |
| 2 | L3 按"来源字符串"计数 | **同一份文书的 8 个不同行 = 8 个字符串，但只是 1 份文书。** 单位应是**文书数**，不是字符串数 |
| 3 | L4 扫全文 → **3 篇已发布文章误报"编造第一人称"** | 命中的是 FAQ 问句 `my supplier will raise prices?`——**读者在问他的供应商，不是作者在叙述自己。** 且把 `illustrative`（规范 5.4 **要求**的模型输入标注）当成骨架标记 |
| 4 | **L1 对草稿永远通过** | **`qa-check` 按设计豁免草稿**（打印 "9 blocking rule(s) not yet met, excluded from the gate" 并返回 PASS / 退出码 0）。**审计存在的意义就是回答"它发布后能不能活"，而用一个跳过未发布内容的检查器来回答，等于没回答。** 现在审计把副本的 `draft:false` 翻过来审 |

**第 4 条最严重：它是"协议要防的事，出现在协议自己的实现里"。**

**而它只被一个动作抓出来——跑一次"应该失败"的用例。**
**所以 preflight 里审计是成对跑的：已发布必须全过，草稿必须全不过。**
**任何一半单独跑，都验不出这个工具是活的。**

## 这个协议挡得住什么、挡不住什么

**挡得住**：没有来源的数字 · 匿名来源 · 日期缺失或不可能 · 只依据一份文书而未声明 ·
编造的经历与面板 · 骨架标记 · 政治/法律/声誉/承诺类风险词

**挡不住**：**来源真实存在、但数字被读错的**（规则 A 那类：`9 34` 被读成 `$9.34`）——
**那只有回原件才能发现。**

**所以 L5 不是"通过就等于安全"，而是"没命中就等于没有人需要现在看一眼"。**
**这两句话的差别，就是自动化可以走到哪一步的边界。**
