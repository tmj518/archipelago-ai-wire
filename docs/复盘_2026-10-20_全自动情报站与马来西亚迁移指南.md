# 全自动数字情报站 - 全面复盘报告

> 复盘对象：`landedmath.com`（中国商业/政策英文解读站）
> 复盘时间：2026-10-20
> 代码基线：`600f3f4`
> 用途：作为马来西亚项目的底层架构模板

## 一、 项目定位与目标

### 1.1 原始目标

**一句话定位：把中国的一手官方数字，变成外国买家发票上的钱。**

| 维度 | 内容 |
|---|---|
| 目标受众 | 海外企业、国外商家、一带一路国家买家 |
| 语言 | 英文（母语级，非翻译腔） |
| 内容形态 | 长文（1200–1800 词）+ 图解 + FAQ + 计算过程 |
| 商业内核 | 每篇文章必须能回答「这对我的到岸成本影响多少」 |
| 排期 | 每周每栏目 1–3 篇，全站每周 ≤15 篇 |
| 长期目标 | 三年 500 万用户，1 年盈亏平衡，网站/博客/短视频/App 闭环 |

### 1.2 核心痛点：为什么不用传统 CMS

| 传统 CMS | 本站的要求 | 结论 |
|---|---|---|
| 人工选题 | 需要每天扫描 11+ 个部委站点 | 人力不可持续 |
| 人工写作 | 每篇 1500 词 + 数字核验 + 计算过程 | 单篇 1.5–3 小时 |
| 人工查重 | 48 篇存量，主题高度集中（关税/反倾销） | 极易撞车 |
| 人工校验 | 21 条结构规则 + 5 层审计 | 人眼会漏 |
| 无成本感知 | 模型调用要看得见花了多少 | CMS 不管这个 |

**★ 根本矛盾：内容质量要求极高（数字必须可核验），但产量要求极高（每天一篇）。这两件事只有自动化能同时满足 —— 前提是自动化本身必须可审计。**

### 1.3 最终达成的量化指标

**存量（截至 2026-10-20）**

```
文章      48 篇
周期      2026-09-22 → 2026-10-20（29 天）
栏目      trade-policy 21 / supply-chain 7 / sourcing 7 / platforms 7 / logistics 6
工具      84 个 .mjs
工作流    4 个（daily / ci / deep-checks / probe-sources）
站点      176 页构建，sitemap 176 条
```

**单篇成本与耗时（实测）**

| 路线 | 模型调用 | 花费 | 耗时 | 成功率 |
|---|---|---|---|---|
| **A（script）** | 2–7 次 | **$0.0038–0.0059** | **105–166 秒** | 高（换题后） |
| **B（agent）** | 70–155 次 | $0.0153–0.0469 | 5–11 分钟 | 中（依赖兜底） |

**★ A 线单篇不到半美分。按每天 1 篇算，一年模型成本约 $2。**

**失败成本（同样重要）**

```
DUPLICATE-SUBJECT   0 次模型调用 / $0
IDLE（日检拦截）    0 次模型调用 / $0
REJECTED            2–7 次调用 / $0.005–0.02
TURN-LIMIT          40–155 次调用 / $0.02–0.19
```

## 三、 核心理论与双线架构（★ 最重要）

### 3.1 为什么要有两条线

```
A 线（script）：确定性保底 —— 每天必须有文章
B 线（agent） ：探索性上限 —— 发现 A 线想不到的角度
```

**设计原则：两条线共享同一份事实底座（信源、台账、站点、门禁），但在"如何决定写什么"上完全独立。**

### 3.2 A 线：剧本路线

#### 设计哲学

```
每一步都是独立进程，有类型化 JSON 契约
每一跳都可单测，都能桩掉
钱花在最少的调用上（2 次：1 研究 + 1 写作）
```

#### 模型分配（★ 关键：两个不同模型，同一份凭据）

```
写作者    volces Ark  →  ep-20251220175517-rjpsc（豆包 1.5 pro 32k）
审核者    volces Ark  →  ep-20251220173606-gzxdg（DeepSeek-V4-Flash）
备用      deepseek 官方 API
```

**★ 为什么必须不同模型：** 审核者若与写作者同模型，等于自己审自己。`lib-llm.mjs` 的 `reviewIsIndependent()` 会报告 `provider|model|credential|none` 四档独立性。

#### 完整流程（伪代码）

```js
// cloud-orchestrator.mjs
function run() {
  if (alreadyPublishedToday("script") && !force) exit(0);      // 幂等护栏

  let directive = readDirective();

  // ① 已发布主题 → 重新研究，最多 3 次
  let tries = 0;
  while (directive.slug && exists(`src/content/blog/${directive.slug}.md`)) {
    if (++tries >= 3) {
      report("DUPLICATE-SUBJECT", "ALL_SUBJECTS_DUPLICATE");
      exit(0);                                                  // 黄色，不是红
    }
    clearDirective();                                           // 必清，否则 research 拿回同一题
    exec("node tools/research.mjs");
    directive = readDirective();
  }

  // ② 数字门槛
  if (directive.figures.filter(substantive).length < MIN_SUBSTANTIVE) {
    report("THIN-DIRECTIVE"); exit(1);
  }

  // ③ 写作 + 修订循环（最多 3 次）
  for (let attempt = 1; attempt <= 3; attempt++) {
    draft = exec("cloud-executor", { directive, revisionIssues });

    // ④ 严格前置检查：把草稿复制到真实集合路径，用【已发布标准】检查
    writeFileSync(`src/content/blog/.qa-tmp-${slug}.md`, draft.replace("draft: true", "draft: false"));
    strict = qaCheck(`.qa-tmp-${slug}.md`);      // 不豁免任何规则
    rmSync(`.qa-tmp-${slug}.md`);

    if (strict.failed) {
      revisionIssues = strict.rules.map(withFixInstruction);    // 带 Fix 回传
      continue;
    }
    break;
  }

  // ⑤ 落盘前 hedges 清洗 + 后置校验
  sanitizeHedges(draft);                                        // may→can, could→can
  stage(`src/content/blog/${slug}.md`);

  if (qaCheck(stagedPath).failed) {                             // 后置闸门
    rmSync(stagedPath);
    report("REJECTED"); exit(1);
  }

  rebuildInstruments(); addInboundLinks(); commitAndPush();
  report("PUBLISHED");
}
```

run 39202962709  PUBLISHED 166s  $0.0059  （含一次换题）

### 3.3 B 线：Agent 智能体路线

#### 设计哲学

```
ReAct：Reason → Act → Observe → Reason …
模型负责"内容判断"，代码负责"边界与事实"
外壳确定性，内核概率性
```

#### 工具集（8 个，按权限分层）

| 工具 | 作用 | 限制 |
|---|---|---|
| `get_gsc_blue_ocean` | Search Console 蓝海词 | 第 4 轮后关闭 |
| `get_ga4_trending` | 读者分类数据 | 第 4 轮后关闭 |
| `get_latest_official_docs` | 官方文件 + 提案主题 | 第 4 轮后关闭 |
| `run` | 跑仓库命令 | 白名单；**120 秒上限**；**禁止跑 cloud-orchestrator / agent-run**（它自己就是流水线） |
| `read_file` | 读文件 | 准备期后只允许 directive 与草稿 |
| `list_dir` | 列目录 | 仅准备期 |
| `write_file` | 写草稿 | **写入即清空重复调用缓存** |
| `check_draft` | 完整质检 | 返回每条规则的 `Fix:` |
| `publish_draft` | 落盘到 blog | 只要求文件存在且 >200 字符 |
| `relaunch` | 放弃当前稿，换题 | **每次运行最多 1 次** |
| `finish` | 交卷 | 说 PUBLISHED 但没发 → 拒绝 |

#### 死循环的解法（这是本项目最贵的一课）

**症状：** 15–30 轮、70–155 次调用、$0.05–0.19，最后 `TURN-LIMIT`，一篇没发。

**根因（四个叠加，缺一不可）：**

```
① publish_draft 要求「上次 check_draft 全绿」
   ★ 而 qa-check 一次报全部规则，草稿几乎永不绿
   ★ 于是它只能写、查、改、查，永远发不出去
② 反馈只有 "FAIL"，没有 "怎么改"
③ 重复调用缓存把它的修复藏起来（写入后不刷新）
④ 兜底代码写在循环内，靠 turn 判断 → 三次运行零痕迹，从未执行
```

**解法：**

```js
// ① 发布不再被 check 锁死
if (!exists(draft)) return refuse("write it first");
if (readFileSync(draft).trim().length < 200) return refuse("effectively empty");
// checkedOk 只用于日志，不再拦截

// ② 反馈带 Fix
const fixFor = (rule) => {
  if (/word|prose/.test(rule)) return "Fix: 扩写。So what 加第二个算例，For you 加第四类读者。";
  if (/figure/.test(rule))     return "Fix: 至少 2 个数字进 figures[] 并带来源/期间/检索日。";
  if (/faq/.test(rule))        return "Fix: 3–5 个问答，每个答案 80–150 词。";
  ...
};

// ③ 写入即清缓存
if (name === "write_file") seenCalls.clear();

// ④ 兜底放到循环外
}  // ← 循环结束
if (published.size === 0) {
  const newest = newestDraft();
  writeFileSync(`src/content/blog/${newest}`, sanitizeFrontmatter(read(newest)));
  finished = { verdict: "PUBLISHED-WITHOUT-FINISH", ... };
}
```

**★ 一句话总结：把该代码拿的决定从模型手里拿回来，把该在外面的代码从循环里挪出来。**

### 3.4 双线的取舍（写给马来西亚项目的判断）

| 维度 | A 线 | B 线 |
|---|---|---|
| 成本 | $0.004 | $0.047（12×） |
| 耗时 | 2 分钟 | 5–11 分钟 |
| 可预测性 | 高 | 低 |
| 能否发现新角度 | 不能 | 能 |
| 失败形态 | 明确（THIN / DUPLICATE / REJECTED） | 模糊（TURN-LIMIT / 强发） |
| 回归测试 | 14 条全桩 | 11 条剧本 |

**★ 建议：新项目先只上 A 线，跑稳 30 篇之后再上 B 线。B 线的价值在"探索"，而探索需要先有"基准"。**

## 四、 数据驱动漏斗设计

### 4.1 三级漏斗

```
第一级  GSC 蓝海词      有搜索需求的人已经有了 → 最强选题
   ↓ 无数据
第二级  GA4 读者行为    有阅读量的栏目 → 值得继续写
   ↓ 无数据
第三级  官方文件兜底    部委今天发了什么 → 永远有货
```

### 4.2 降级策略的实现

**agent 侧（提示词 + 工具返回值）：**

```js
// get_gsc_blue_ocean 命中
"Search Console has keywords for you:
  - \"china tariff rebate\" 120 impressions, 0 clicks, position 8
Write about the first one, and use get_latest_official_docs to find the rate behind it."

// GSC 未命中（新站常态）
"no blue-ocean keywords. GSC: 0 keywords, falling back to official docs.
 A new site has little or no exposure, so fall through to get_ga4_trending."
```

**script 侧（阈值阶梯 + 明确日志）：**

```js
const LADDER = [
  { label: "strict",         minImpressions: 1000, maxCtr: 0.01, minPosition: 5,  maxPosition: 20 },
  { label: "loose",          minImpressions: 10,   maxCtr: 0.05, minPosition: 3,  maxPosition: 30 },
  { label: "any impression", minImpressions: 1,    maxCtr: 1,    minPosition: 1,  maxPosition: 100 },
];

// 严格档空就往下走，并打印是哪一档出的结果
for (const rung of LADDER) {
  rows = withinLadder(all, rung);
  if (rows.length) { log(`ladder: strict 空，${rung.label} 找到 ${rows.length}`); break; }
}

log(blue.length
  ? `GSC BLUE OCEAN: Found ${blue.length} keyword(s) - these drive the subject`
  : `GSC: 0 keywords, falling back to official docs`);
```

### 4.3 新站的现实（非常重要）

```
site      : sc-domain:landedmath.com
credentials: read as raw JSON - the secret holds the key document itself
token     : ok
query     : ok - 5 query row(s)        ← Google 已经在返回真实数据
matched   : 0                          ← 但曝光量还不到任何一档门槛
GSC: 0 keywords, falling back to official docs
```

**★ 结论：GSC 接入是成功的，但站点需要 1–3 个月积累曝光，蓝海词才会出现。在那之前，第三级兜底是唯一有货的源。这不是失败，这是新站的必经阶段。**

## 五、 终极防线：六大兜底与容错机制

### 5.1 双 Cron 防跳票

**问题：** 2026-10-19 的 07:20 定时**完全没有触发**，无日志、无痕迹。GitHub 的 cron 是 best-effort，高峰期会整次跳过。

**解法：**

```yaml
- cron: '20 23 * * *'   # 07:20 北京  script
- cron: '20 1 * * *'    # 09:20 北京  script 备用
- cron: '20 12 * * *'   # 20:20 北京  agent
- cron: '20 13 * * *'   # 21:20 北京  agent 备用
```

**★ 备用 cron 只有在有幂等护栏时才安全 —— 否则会各发一篇。**

### 5.2 路线级幂等护栏

```js
function alreadyPublishedToday(route) {
  const beijingToday = new Date(Date.now() + 8*3600e3).toISOString().slice(0,10);
  for (const f of readdirSync("data/runs")) {
    const j = JSON.parse(read(f));
    if (j.route && j.route !== route) continue;          // ★ 按路线隔离
    if (j.noNewPage) continue;                            // ★ 没产出新页面不算
    const when = new Date(new Date(j.at).getTime() + 8*3600e3).toISOString().slice(0,10);
    if (when === beijingToday && /^PUBLISHED/.test(j.verdict)) return j;
  }
  return null;
}
```

**★ 两个坑都踩过：**
```
① 不分路线 → 脚本一发，agent 永远跳过 → 系统正常工作的每一天 B 线都被自己杀掉
② 强发覆盖了昨天已发布的文件 → 记成"今天已发" → agent 被误杀一整天
```

### 5.3 查重顺延与换题

**A 线：**

```js
while (已发布 && tries < 3) {
  clearDirective();                    // 必清，否则 research 拿回同一题
  exec("node tools/research.mjs");     // research 自己有 3 次提案 + 日期限定兜底
  directive = readDirective();
}
if (still 已发布) { report("ALL_SUBJECTS_DUPLICATE"); exit(0); }
```

**B 线：**

```js
relaunch()   // 放弃当前稿 → 跑 research → 返回新主题 + 数字清单
             // 每次运行最多 1 次；不限次会变成另一种死循环
```

**查重的两把尺子（必须都满足才拦）：**

```js
const strong = sharedValues.length >= 1              // 有共享的实质数字
            || (sameMeasure >= 2 && sharedOrg >= 1); // 或同一措施 + 同一机构
const score = strong ? sharedValues*3 + sameMeasure*2 + sharedOrg : 0;
if (score >= 6) reject;
```

**★ 为什么不能只看关键词：这个 beat 有一百篇文章，它们全都共享 `duty` / `importer` / `screening`。用词重合不是重复的证据。**

### 5.4 硬美元预算上限

```js
const USD_LIMIT = Number(process.env.AGENT_USD_LIMIT ?? 0.06);
// 每次工具调用后检查（不在循环条件里，因为调用是记账后才算钱）
if (usageToday().usd >= USD_LIMIT) {
  log(`budget: $${spent} 达到 $${USD_LIMIT} 上限，结束运行`);
  break;   // 走兜底交卷
}
```

**★ 为什么轮数预算不够：** 今天的 agent 跑了 70 次调用，其中 **56 次是重试**。第 9 轮在重试风暴里和第 9 轮在顺畅运行里长得一模一样 —— 只有美元能看见差别。

### 5.5 循环外强制交卷

```js
// ★ 在循环外面，只问一个问题：发文了吗？
if (published.size === 0) {
  const newest = newestDraft("data/drafts");
  if (newest && read(newest).trim().length > 200) {
    writeFileSync(`src/content/blog/${newest}`, sanitizeFrontmatter(read(newest)));
    published.add(slug);
    finished = { verdict: "PUBLISHED-WITHOUT-FINISH",
                 summary: "循环结束未交卷，已按最新草稿发布" };
  }
}
```

**★ 反面教材：** 同样的逻辑写在循环内、用 `turn >= MAX_TURNS - 2` 判断，三次运行**日志里零痕迹**，一次都没执行。移到循环外，第一次就成了。

### 5.6 外部接口失败自动降级

| 接口 | 失败时 | 是否阻塞 |
|---|---|---|
| GSC 密钥缺失/解码失败 | `exit 0` + WARNING + 修复命令 | ❌ |
| GSC 查询 0 行 | `exit 0`，写空结果 | ❌ |
| GA4 无数据 | `exit 0`，返回"无读者数据" | ❌ |
| 单个 provider 掉线 | 计数，只要一个能通就继续 | ❌ |
| 全部 provider 掉线 | `NO-KEYS`，红色 | ✅ |
| 构建失败 | `exit 1` | ✅（这是真的坏了） |

**★ 原则：数据源缺失是"降级"，构建/密钥全灭才是"失败"。两者的颜色必须不同。**

## 六、 近一周踩坑与避坑指南（血泪教训）

### 6.1 编码坑 ★★

**症状：**
```
credentials : GSC_CREDENTIALS_BASE64 does not decode to JSON
  base64:           '\uFFFD^\uFFFD\uFFFD\u04F7k\uFFFD\uFFFD^' is not valid JSON
  base64 of base64: '\uFFFD\uFFFD9\uFFFD' is not valid JSON
```

**根因：**
```powershell
# 错误的做法（PowerShell）
[Convert]::ToBase64String([Text.Encoding]::Unicode.GetBytes($json))
#   → 得到的是 UTF-16 文本的 base64
#   → 云端的 Buffer.from(x,'base64').toString('utf8') 读成乱码

# 正确的做法
[Convert]::ToBase64String([IO.File]::ReadAllBytes("key.json"))
```

**★ 更彻底的解法：直接把原始 JSON 粘进 secret。** GitHub 反正会加密存储。

**避坑三条：**
```
① 先看头字节：FF FE = UTF-16LE, EF BB BF = UTF-8 BOM
② 解码器要能认 raw JSON / base64 / base64-of-base64 / utf16le / gzip 五种
③ 失败时必须打印 first bytes 的十六进制，否则永远在猜
```

### 6.2 锁死坑 ★★★（最贵的一个）

**症状：** 15–30 轮、70–155 次调用、$0.19，`TURN-LIMIT`，零发布。

**根因：**
```js
if (!checkedOk.has(input.path)) {
  return done("REFUSED: has not passed check_draft");
}
// ★ 而 check_draft 一次报全部规则 → 草稿几乎永不绿 → 发布永久被拒
```

**解法：** 见 5.5 / 3.3。**发布只要求"文件存在且非空"，质量由 check_draft 建议、由后置闸门兜底。**

**避坑：** 任何"必须先通过 A 才能做 B"的链条，都要问一句：**A 有可能永远通过不了吗？** 如果是，链条就是死锁。

### 6.3 缓存坑 ★★

**症状：**
```
turn 9  write_file   (改了文件)
turn 10 check_draft  → "repeated, answered from memory"   ← 返回旧结果
turn 11 check_draft  → "repeated, answered from memory"
turn 12 重写成 v2    turn 14 重写成 v3 → TURN-LIMIT
```

**根因：** 重复调用缓存键是 `(工具, 参数)`，不看文件内容。

**解法：**
```js
if (name === "write_file") seenCalls.clear();
```

**避坑：** 任何"记忆化"都要先问：**被缓存的答案依赖哪些会被修改的状态？**

### 6.4 格式坑 ★★★（把站点搞挂的那次）

**症状：** 流水线报 `PUBLISHED`，但整个站点 404 了 25 分钟。

**根因：**
```yaml
information_gain: primary-source-analysis   # 枚举里只有 primary-source
publishDate: <对象>                          # 应是日期
audience: importer                           # 枚举要 "both"
priority: 50                                 # 枚举要 "P0"/"P1"/"P2"
```
Astro 的 `InvalidContentEntryDataError` → 构建失败 → Cloudflare 不部署。

**解法（两道）：**
```js
// ① 强发前自动清洗
const GAIN = ["custom-calculation","cross-source","own-data","primary-source"];
set("information_gain", GAIN.includes(raw) ? raw : "primary-source");
if (!/^(platform-seller|importer|both)$/.test(aud)) set("audience", '"both"');
if (!/^(P0|P1|P2)$/.test(pri)) set("priority", '"P2"');
if (!/^\d{4}-\d{2}-\d{2}$/.test(date)) set("publishDate", today());

// ② 落盘后立刻再查一次 qa-check（草稿豁免在真实路径上不生效）
try { execFileSync(node, ["tools/qa-check.mjs", target]); }
catch { rmSync(target); published = false; }
```

**避坑：** **绕过闸门不等于绕过 schema。** 任何"强制发出去"的路径，都必须自己承担校验责任。

### 6.5 截断坑 ★

**症状：** 同一份提示词，一次 2043 词（超上限），一次 859 词（不到下限）。`may` 这个词让三次修订全死。

**根因：**
```
① 提示词只说了"带成本表时 1200–1800 词"，没说"不带成本表时多少" → 模型写了 789
② 计数口径（渲染后正文）比写作时的直觉长约 5%
③ 禁词规则连月份 May 一起禁
④ 清洗器跑在闸门【之后】
```

**解法：**
```
① 两种档位都写进提示词
② 上下限按实测放宽（100–2100 / 100–2600）
③ may/could 用确定性替换（sanitize），且【在闸门之前】跑
④ 禁词规则降级为"报告项"，不拦发布
```

**避坑：** **风格问题不该拦住发布，事实问题必须拦住。** 分清这两类，闸门才不会把系统锁死。

### 6.6 其他值得记住的坑

| 坑 | 症状 | 解法 |
|---|---|---|
| YAML 重复键 | `Map keys must be unique`，工作流完全不触发 | `check-workflow-yaml.mjs` |
| shell 里的 `/*` | `/bin: Is a directory`，exit 126 | 用 `#` 注释；`check-workflow-shell.mjs` |
| 台账幽灵条目 | 提过但没发的主题永久封禁 | 提案写 `data/proposed.jsonl`，不进台账 |
| 两个查重守卫打架 | score 0 通过，slug 守卫拒绝，三次全撞死 | slug 已存在直接算 99 分 |
| 单个 provider 抖动 | HTTP 000 杀掉整次运行 | 改计数，一个能通就继续 |
| 组件初始化顺序 | `ReferenceError: Cannot access 'publishDate' before initialization` | 把约束块移到变量声明之后 |
| PowerShell 口径 | `Set-Content` 带 BOM、`>` 写 UTF-16、CRLF 残留 `\r` | 用 `[IO.File]::WriteAllText` + UTF8 无 BOM；读日志走 stdin |
