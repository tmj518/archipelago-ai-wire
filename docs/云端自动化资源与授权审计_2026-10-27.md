## 6. 目标架构与数据流（方案 A）

选择 **方案 A：GitHub Actions schedule + 现有 Node 工具**。理由：所有能力已有代码、已有测试、已在本机跑通；引入 n8n 会新增一套需要运维的系统，而第一阶段唯一缺少的是**调度**，不是编排引擎。

```
                  ┌──────────────── GitHub Actions（schedule，每日）────────────────┐
                  │                                                              │
  RSS/官方公告 →  research.mjs ─→ store-source.mjs ─→ data/sources/             │
                  │        ↓                                                     │
  GSC（只读）  →  gsc-report / query-gap / blue-ocean ─→ 选题候选              │
                  │        ↓                                                     │
                  │  build-directive.mjs → cloud-executor.mjs（AI，带重试与记账）│
                  │        ↓                                                     │
                  │  qa-check（24 block）→ 10 道闸门 → check-publish-ready       │
                  │        ↓ 全绿才继续                                          │
                  │  commit 到 main（生成与发布分离：PR 或受保护分支）           │
                  └──────────────────────────────────────────────────────────────┘
                                   ↓ push main
                        Cloudflare Pages 构建并发布
                                   ↓
             data/outcomes（D7/D28）+ data/reviews（盲评）+ eval-loop
                                   ↓
                        下一轮选题与提示词决策（人工审批）
```

**幂等要求**：同一选题重复运行不得重复发布 → 以 `data/content-ledger.json` + slug 作为幂等键。
