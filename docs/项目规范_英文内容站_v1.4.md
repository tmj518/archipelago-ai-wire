## 一、定位与受众（2026-10-01 确认）

### 1.1 一句话定位

**把中国的商业政策读成钱。**

中国发布大量贸易信息——关税表、海关公告、平台规则、工业统计——几乎全部为国内读者写作，语言面向政策圈而不是买家。Landed Math 做**翻译层**：取一次文献，找出关键数字，算成每件、每柜的到岸成本，给下单的人看，而不是给写通稿的人看。

### 1.2 身份主张（重要）

| 项目 | 决定 |
| --- | --- |
| 自我表述 | **帮世界读懂中国的商业政策** |
| 立场 | 懂中国、对中国友好，但**不代表任何一方** |
| 明确否认 | About 页必须写明"Not a mouthpiece"：不受任何政府、商会、贸易机构资助或代言 |
| 禁止表述 | "向世界说出中国的声音"这类代表某一方的宣示 |

**理由**：AI 引擎（ChatGPT / Perplexity / Claude）对独立来源的引用权重高于口径渠道；而"代表某一方"会同时削弱 GEO 效果与容错空间——一个数字错了，性质会从编辑失误变成立场问题。

### 1.3 受众（增量策略，不是替换）

| 受众 | 需求 | 对应栏目 |
| --- | --- | --- |
| **欧美平台卖家**（Amazon / Temu / TikTok Shop / D2C） | 规则变化对本季毛利的影响 | `platforms`、`trade-policy` |
| **一带一路及新兴市场进口商与买家**（东南亚 / 中东 / 非洲 / 拉美） | 怎么找厂、要什么单据、目的国怎么清关、怎么结算 | `sourcing`、`logistics` |
| 两者共同 | 供应链与产能 | `supply-chain` |

每篇文章的 frontmatter 必须声明 `audience`（`platform-seller` / `importer` / `both`），并在文章页 meta 行显示为 "For Platform sellers" / "For Importers & buyers"，让读者一秒判断适用性。

### 1.4 语言

第一阶段**纯英文**。把英语当"一带一路商业通用语"。跑通后再评估阿拉伯语 / 俄语 / 西语 / 印尼语。

## 三、站点结构

### 3.1 五个栏目（slug 即 URL，改一次要写 301）

| slug | 显示名 | 面向 | 覆盖 |
| --- | --- | --- | --- |
| `trade-policy` | Trade Policy | 平台卖家 | 关税、反倾销、出口管制 |
| `platforms` | Platforms | 平台卖家 | Amazon / Temu / TikTok Shop / EU 合规 |
| `supply-chain` | Supply Chain | 两者 | 工厂、产能、物流、工业数据 |
| `sourcing` | Sourcing & Suppliers | 进口商 | 找厂、验厂、打样、MOQ、支付条款 |
| `logistics` | Logistics & Customs | 进口商 | 运费、单据、目的国清关、Incoterms |

**URL 规则（2026-10-02 定）**：文章 `/blog/<slug>/`，栏目页 `/category/<slug>/`。

**为什么不改成 `/<栏目>/<slug>/`**：URL 形状对排名的实际影响很小，内容质量和信息增量才是决定性的；而改结构要动内链、RSS、sitemap，属于"有风险的低收益改动"。此决定已冻结。

### 3.2 frontmatter 标准（完整字段表）

```yaml
---
# —— 内容 ——
title: "..."                      # ≤120 字符
description: "..."                # ≤300 字符，同时用作 meta description 与卡片摘要
publishDate: 2026-10-02
updatedDate: 2026-11-15           # 可选；有更正或回改时填
category: "trade-policy"          # 五个 slug 之一（用 slug，不用显示名）
audience: "platform-seller"       # platform-seller | importer | both
tags: ["tariffs", "landed cost"]
priority: "P0"                    # P0 行业级 / P1 板块级 / P2 观察
featured: false                   # true 时进首页 Hero
draft: true                       # true 则完全不出现在站点、RSS、sitemap

# —— 选题与闸门（必填）——
target_keyword: "section 301 exclusions expiration november 2026"
search_intent: "informational"    # informational | transactional | comparison
information_gain: "custom-calculation"
    # custom-calculation 自有计算 | cross-source 跨源比较
    # own-data 自有数据 | primary-source 一次文献直读

# —— 数字与来源（§5.3 的机器化）——
figures:
  - value: "178"
    unit: "product exclusions"
    period: "as of 1 December 2025"
    source: "USTR, Notice of Product Exclusion Extensions, 90 FR 55232"
    retrieved: "2026-10-01"
sources:
  - "Ministry of Commerce of the PRC, press conference, 2026-09-29"

# —— 媒体 ——
heroImage: "/images/xxx.png"
heroImageAlt: "..."
---
```

### ★★ 3.4 文书页（`/instrument/<slug>/`）—— v1.4 新增

**这是本站"可引用单元"的实现，也是对标学习第 1 条的正确落地方式。**

#### 为什么不是 `/figure/<slug>/`

**2026-10-08 实测，结论推翻了原本的计划**：

```
207 条 figure 记录 → 199 个不同数据点     复用率 1.04x
被 ≥2 篇文章引用的                         8 个（其中 4 个是同一篇内的重复）
被 ≥3 篇文章引用的                         0 个
```

**→ 给每条 figure 一个 URL = 199 个"页面里只有一个数字"的薄页。**
**那正是"不做产量路线"要避免的东西，而且 Google 会把这种归为薄内容。**

#### 为什么是文书层

**同样 207 条 figure，只来自 131 份文书**（平均每份供出 1.58 个数字）：

```
供出 ≥2 个数字的文书         35 份
被 ≥2 篇文章引用的文书        7 份
两者取并集，再排除"Landed Math 模型"（那是我们的算术不是外部文书）
→ 当前生成 28 页，覆盖 90 条 figure
```

> **★ 关键判断：OWID 的可引用单元不是"数字"，是"数字来自的那份东西"。**
> **同一份关税附件往往供出好几个数字，被好几篇文章引用——它才是节点。**

#### 一页里有什么（这是"不薄"的原因）

| 内容 | 作用 |
| --- | --- |
| **该文书的全部 figure**（表格式五元组） | 数据单元 |
| **引用它的全部文章**（反向链接） | 让它成为节点，而不是孤立页 |
| **"Source as cited" 原文** | 可信度锚 |
| **Cite this 引用块** | **对标学习第 2 条：机器可读的引用接口** |
| **`Dataset` JSON-LD**（`isBasedOn` 指向文书本体） | 结构化数据，让 AI 引擎能引用 |

#### 页面是生成的不是手写的

```
node tools/build-instruments.mjs          生成注册表
node tools/build-instruments.mjs --check  检查是否与文章同步（preflight 会跑）
```

**注册表 `src/data/instruments.json` 由文章 frontmatter 派生。**
**所以页面数量跟着数据走**：当后续文章从同一份文书里取更多数字、跨过深度阈值时，**页面自动出现，不需要有人编辑清单。**

#### 排除规则

| 排除什么 | 为什么 |
| --- | --- |
| **`Landed Math <模型名>` 来源**（25 条） | **那是我们自己的算术，不是外部文书。** 它属于方法论，不属于文书目录 |
| **只供出 1 个数字且只被 1 篇引用的文书**（当前 78 份） | **一个数字不值得一个 URL。** 等后续文章从同一来源取更多数字时自动进来 |

#### 诚实说明必须留在索引页上

**`/instrument/` 索引页显式写着**：

> Documents that supplied a single figure are not listed here yet — **a page holding one number is not worth a URL.** They join this index as later articles draw more from the same source.

**这既是给读者的说明，也是给我们自己的约束记录。**

## 五、内容生产 SOP

### 5.1 写作模板 V6.2（每篇固定结构）

> **本节于 2026-10-08 由 V6.1 更新为 V6.2。** 三处改动，理由在表后。
> **改动原因**：① 用户定的第一标准是完成度而非字数（见 `初心与目标.md` 的"第一标准"节）；
> ② 对标研究发现所有免费来源都只说一面，而"承认局限"是唯一没人做的护城河；
> ③ 实测中位 1,914 词，而 Backlinko 的 1,180 万搜索结果显示首屏均值 1,447 词、字数与排名无直接关系。

**★ 第一标准：完成度 > 搜索意图 > 有价值。字数只是结果，不是目标。**（2026-10-08 用户定）

| 段 | 内容 | 目标字数 |
| --- | --- | --- |
| **AI Summary** | 60-100 词，**结论先行**：判断是什么 + 对谁意味着什么 | 60-100 |
| **Hook**（无小标题） | 抛出反常识点 | ~100 |
| `## What happened` | 精确数字 + 政策原文 | 200-300 |
| `## Why now` | 政策脉络（追溯 2-3 年）+ 时间窗口 | 100-200 |
| `## So what` | 判断 + 成本测算 + 反常识点 | 250-350 |
| **`## How confident`** | **★ 新增**：已确认 / 推断 / 什么情况下我会错 | 100-180 |
| `## For you` | ≥3 组分人群建议 + 行动清单 | 150-250 |
| `## The data point` | 一个关键数字收尾（用 `.callout` 块） | 60-100 |
| `## FAQ` | **3 问**（原 3-5），答案各 80-150 词 | 240-400 |
| `## How we calculated this` | 算式（代码块） | 50-120 |
| `## The point` | 收尾判断 | ~100 |

**字数：下限 1,000 · 目标 1,200–1,800（带成本表）/ 1,200–1,600（不带） · 上限 2,500（带成本表）/ 1,800（不带）**

> **★ 上限是防注水的，不是防覆盖的。**
> **带成本表的题有结构下限**——实测 4 张表格 + 定义块 + 计算节 + callout ≈ 450 词非叙述内容，
> 加三问 FAQ 和 `How confident`，**真实下限约 1,950 词**。
> **档位由闸门从正文里的金额表自动判定，不用声明。**

必须包含 **≥1 个对比表** 和 **≥1 个定义块**（用引用块 `> **术语** — 释义`）。

**★★ V6.2 新增的 `## How confident` 是本文档里最重要的差异化设计**，三段缺一不可：

```markdown
## How confident

**已确认（原始文献支撑）** —— 一句一条，每条挂 figure 或具名来源
**推断（我的判断，证据不直接支撑）** —— 并说明推断依据什么
**什么情况下我会错** —— ★ 至少一条，写清什么条件下这个判断不成立
```

**为什么它必须放在正文前部而不是末尾**：**NN/g 眼动数据——第一屏占 57% 的注意力、前两屏 74%。**
**信任必须在第一屏建立，而"承认局限"是所有免费来源（官方外宣、自媒体）都不写的。**

**★★ 标注规则（同 V6.2 新增）**：**默认是"已确认"**（五元组撑着）。
**只在不是事实时才标【推断】或【观点】。绝不允许把推断写成事实**——那正是这个站要区别于自媒体的地方。

### 5.2 每篇文章必须有的元素

| 元素 | 要求 |
| --- | --- |
| 精确数字 | ≥5 个，每个都要满足**五元组**（见 5.3） |
| 成本测算 | ≥1 个，**必须来自 §7 的成本模型库**，不接受即兴计算 |
| **★ 置信度分段** | **`## How confident` 三段齐**：已确认 / 推断 / 什么情况下我会错 |
| **★ 论断标注** | 非事实的论断标【推断】或【观点】，**不许把推断写成事实** |
| 明确观点 | 不和事佬，要"Don't do X. Do Y." |
| 反常识点 | "Most sellers think X, but actually Y" —— X 必须是有出处的大众认知，不能是编造的稻草人 |
| 分人群建议 | ≥3 组，按受众或按经营方式切分 |
| 政策时间线 | 追溯 2-3 年 |

### 5.3 数据防线（五元组，硬规则）

**每个数字必须携带五项**：数值 + 单位 + 时间 + 具名来源 + **抓取日期**。

- 抓不到来源 → 标"待核实"
- **含"待核实"数字的文章不得置为 published**
- "待核实"数字超过 2 个 → 该选题退回选题池
- 信源只认：海关总署 / 商务部 / 统计局 / 新华社 / CCTV / 目的国官方机构 / 一次文献（Federal Register、欧盟官方公报、公告编号）

### 5.4 人工痕迹条款（v1.3 重写）

原 v1.0/v1.2 的"第一人称经验"在**零人工审稿**下只能靠编造，故改写：

| 元素 | 现行要求 |
| --- | --- |
| 第一人称经验 | **改为"分析师追踪陈述"**：只允许可由公开数据支撑的观察（"Tracking this since 2024, three of four adjustments followed the same sequence"） |
| 具体金额 / 损失 / 客户案例 / 样本量 | **若无公开可核实的来源，一律不得出现** |
| 成本测算 | 必须来自模型库，且模型输入（FOB、数量、费率）**必须在正文标注为假设**，不得冒充事实 |

### 5.5 英文门禁

- 按 Bloomberg / FT 风格写
- 禁止 AI 套话（`delve` / `landscape` / `in today's fast-paced world` / `it's important to note` / `when it comes to` …）
- 禁止逐字翻译
- 禁止模糊词：`may` / `might` / `possibly` / `perhaps` / `could` / `reportedly` / `allegedly`
  （注：月份 `May` 首字母大写，不受此限；闸门按大小写区分）

> **★ 2026-10-08 新增 `tools/gate.mjs`**：一次跑全部 7 项闸门，并行了快的那些，且按输入哈希缓存。
> **实测：冷启动 226 秒 → 热启动 0.1 秒；改一篇文章后再跑全部闸门 = 1 秒。**
> （之前手动逐个跑一次要 5.5 分钟，其中 81% 是重复联网抓竞品页。）

### 6.1 闸门一：`tools/qa-check.mjs`

**阻断项**（任一失败即 BLOCK）：

数字五元组完整 · `figures[]` ≥5 条 · `information_gain` 已声明 · `target_keyword` 已声明 ·
**AI Summary 40-100 词**（V6.2 放宽）· **V6.2 结构齐全**（含 `## How confident`）·
**`## How confident` 三段齐**（已确认 / 推断 / 什么情况下我会错）·
FAQ **3 问**且答案 80-150 词 · **字数在下限 1,000 与所在档上限之间**（带成本表 2,500 / 不带 1,800）·
对比表与定义块存在 · 分人群建议 ≥3 · 无模糊词（**表"允许"义的 `may` 已排除**）· 无 AI 套话 · 敏感词黑名单 · 正文无 URL

**警告项**（不阻断）：具名来源 <3 · FAQ 答案长度越界 · 缺少政策时间线 · `draft: true` ·
**V6.2 之前发布的旧文**（`## How confident` 与字数规则均**永久豁免**，只 warn）

### 6.2 闸门二：`tools/serp-check.mjs`（信息增量）

抓目标词的竞品页面，逐条验证 `information_gain` 声明：

| 声明类型 | 机器判定 |
| --- | --- |
| `custom-calculation` | 本文必须有带金额的每件/每柜成本表，且竞品中 ≤1 个有同类计算 |
| `primary-source` | 本文必须引用一次文献编号（FR / 公告号 / HTSUS），且竞品中 ≤1 个引用 |
| `cross-source` | 本文 ≥2 个具名来源，且竞品中 ≤1 个有相当数据密度 |
| `own-data` | **机器无法验证 → INCONCLUSIVE，转人工** |

**三条设计原则**：

1. **SERP 来源可插拔**：`--serp=bing`（best-effort 抓取）或 `--serp=file:<快照>`（由 Agent 搜索工具或付费 SERP API 产出，快照放 `data/serp/<文章名>.json`）
2. **官方源不算竞品**：`.gov` / `customs.gov.cn` / Federal Register / 新华社 / 中国网 等一次文献发布渠道会被识别并**排除出竞品分母**——那是输入，不是竞争
3. **抓不到就拒绝盖章**：无 SERP、SERP 与关键词不相关、竞品页面全部加载失败 → 一律 `INCONCLUSIVE`，**绝不返回 PASS**
4. **零竞品 ≠ 不合格**：没人竞争时"我比他们多什么"不可能为假，声明**平凡成立**；此时输出**需求警告**，提示单独验证搜索量（这是需求问题，不是增量问题）

## 七、成本模型库

**这是产能的真正来源，也是信息增量的供给源。** 同一批公开数字，你算出的结果别人没有。

| 模型 | 文件 | 算什么 |
| --- | --- | --- |
| 到岸成本 | `tools/landed-cost.mjs` | FOB × (MFN + 301 + 其他) → 每件 / 每柜 |
| 税款担保 | `tools/guarantee-cost.mjs` | 担保占用资金的成本（提前放行的代价） |
| 持有成本 | `tools/hold-cost.mjs` | 下架损失边际贡献 / 扣货的资金占用 |
| 退税传导 | `tools/rebate-passthrough.mjs` | 退税点数 → 单价金额 |
| 图片 | `scripts/make-og-image.mjs` | 生成默认分享卡 |

**使用规则**：文章里的成本测算**必须调用模型**，不允许在正文里即兴算术。模型输入（FOB、数量、费率）是读者的输入，**必须在正文标注为假设**；只有税率、日期这类**可查证的东西**才是事实。

**下一批候补模型**：平台费率（Amazon referral / FBA）、汇率与账期、质检与验货成本、退货运费。

## 八、数据回流闭环

每周拉一次 GSC，按下表自动判定并生成动作：

| 信号 | 判定 | 动作 |
| --- | --- | --- |
| 有曝光 · 无点击 | 标题/描述不吸引 | 生成 title/description 改写候选 |
| 有排名 · 曝光极低 | 索引或抓取问题 | 检查是否被索引、sitemap 收录、内链 |
| 点击尚可 · 停留差 | 内容与搜索意图不匹配 | 重写 AI Summary 与 Hook |
| **30 天零曝光** | 选题错 **或** 质检漏检 | **先重跑闸门**：通过 → 选题问题，退回选题池；失败 → 漏检，进规则修订 |
| 出现未瞄准的新 query | 意外的真实需求 | 直接进下周选题池 |
| 某篇被 AI 引用 | GEO 命中 | 反拆它命中了哪条信息增量，复制到同类文章 |

**第 4 行是自校准机制**：不需要人读文章，用"零曝光"这个客观信号反查闸门是否失效。

**节奏约束**：每周 3-4 篇，质量优先；单日发布上限 1 篇；**年度总量不作为 KPI**（总量目标诱发赶工，赶工直接击穿数据防线）。

**主指标**（按优先级）：

| 指标 | 为什么 | 采集 |
| --- | --- | --- |

## 十二、内容红线

1. **不编造数据**。不确定的标"待核实"，且含待核实数字不得发布
2. **不写敏感政治、民族、领土话题**；`qa-check` 有敏感词黑名单硬阻断
3. **不冒充官方机构**
4. **不冒充代表任何一方**（见 §1.2）
5. **禁止无法核实的个人经历与金额**（见 §5.4）
6. 视频传 YouTube，不放进 Git 仓库
7. **全站页脚必须有免责声明**（2026-10-07 修订，原文为"每篇文章底部：`Independent analysis, not financial or legal advice`"）
   - **实际措辞**（单一来源 `src/consts.ts` 的 `DISCLAIMER`，由 `src/components/Footer.astro` 渲染）：
     > `Analysis of publicly available official documents. Not a customs broker, law firm or tax adviser, and nothing here is legal, tax or investment advice. Every figure is sourced and dated — check the original before you act on it.`
   - **为什么改**：原文那句要求的**精确字符串从未在任何页面出现过**——实现一直是这句更长的。**规范落后于实现，而不是实现违反了规范。**
   - **为什么放在站点页脚而不是每篇底部**：每页都带页脚，文章页再重复一遍是**同一屏说两次**（`ArticleFooter.astro` 有注释记录这个决定）。
   - **它覆盖原文要求的三件事**：公开官方文件的分析（=independent）· 不是律所/税务顾问 + 不是法律/税务建议 · **并多了一条可操作的**"每个数字都有出处和日期，行动前查原文"。
   - **检查器**：`qa-report.mjs` 的 `DISCLAIMER` 正则已改为匹配**真实渲染的措辞**。**这是自检查的**——改措辞而不同步那一行，正则失配、过滤失效、结尾重合率会飙到 100% 从而暴露问题。
