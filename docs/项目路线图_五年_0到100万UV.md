## 一、先回答"明天发几篇"

**问题**：明天继续更新吗？更新几篇，每个栏目？

**回答**：**继续，但不要按"每栏目每天 1 篇"来。**

v1.3 §8 已定死两条约束：**每周 3-4 篇，质量优先**；**单日发布上限 1 篇**。所以"5 个栏目每天各 1 篇"= 每天 5 篇，违反规范，而且会直接击穿质检闸门——因为闸门要求每篇有 ≥5 个带五元组的数字，这个量级的产出必然导致编造。

**建议节奏：每周 5 篇，每栏目 1 篇。**

| 项 | 数值 |
| --- | --- |
| 每周产出 | 5 篇（每栏目 1 篇） |
| 每天产出 | 1 篇（正好卡在单日上限） |
| 每年产出 | 约 250 篇（含节假日损耗） |
| 每栏目每年 | 约 50 篇 |

**为什么这个节奏是对的**：5 个栏目均衡 → GSC 数据出来时你有一组可比较的样本；而如果某个方向先起量，你随时可以把 5 篇的配比调成 3:1:1（这是"方向加倍期"要做的事）。

**为什么不是更多**：这个站的护城河是**信息增量**（自有计算 + 一次文献直读），不是产量。产量路线你已经明确否决过（MoGrow 那套），而且产量路线的终点是规模化内容滥用。

## 二、目标拆解：100 万月 UV 到底意味着什么

先把数字摊开，因为"100 万 UV"这句话在不同人嘴里差十倍。

**100 万月 UV ≈ 每天 3.3 万访客 ≈ 每月约 130 万 PV（按 1.3 页/访客）。**

### 2.1 单靠英文文章能不能到？

不能。用行业里可验证的量级算：

| 单篇成熟期月访问（利基 B2B 长尾） | 达到 100 万 UV 所需文章数 |
| --- | --- |
| 50 | 20,000 篇 |
| 100 | 10,000 篇 |
| 300（乐观，需抢中等词） | 3,300 篇 |
| 1,000（需大词 + 品牌） | 1,000 篇 |

按每周 5 篇，一年 250 篇，五年 1,250 篇。**在"单篇 100 次/月"的现实假设下，五年只能到约 12.5 万月 UV。**

### 2.2 所以 100 万必须靠乘数

| 乘数 | 作用 | 现实倍数 |
| --- | --- | --- |
| **多语言** | 每个语种是独立的关键词市场，不是翻译的附属品 | ×2.5 – 4（4-5 个语种） |
| **视频** | YouTube 是独立发现引擎，且能反哺站点权重 | ×1.2 – 1.5 |
| **AI 引用** | 带来品牌搜索与直接访问 | ×1.1 – 1.3 |
| **邮件列表** | 复访率，且不依赖算法 | ×1.1 – 1.2 |

**12.5 万 × 3（语言）× 1.3（视频）× 1.15（AI）× 1.15（邮件）≈ 64 万。**

**结论**：100 万月 UV 在五年内**可达但不是基线情形**，需要：
1. 文章累计到 **1,200-2,000 篇**（含多语种）
2. **至少 3 个语种**（英语 + 西语 + 葡语，见 §5.1）
3. **YouTube 做成第二条产线**（不是顺手发）
4. 三个乘数**同时**成立

**如果只做英文，五年现实区间是 15-30 万月 UV。** 这是诚实的分歧点，也是你要拍板的地方。

## 四、KPI 纪律（v1.3 §9 已定，此处重申）

**主指标**：订阅数 > GSC 曝光量 > 被 AI 引用次数。

**明确不以"访问量"为主指标**：AI Overview 出现时传统结果 CTR 下降约 61%。如果按访问量做 KPI，你会在第 6-9 个月看到增长慢于预期，然后本能地去加产量、加平台、买工具——**那正好走回规模化内容滥用的路**。

## 五、逐项落地设计

### 5.1 多语言（对应第 3 项）

**原则：不是"翻译"，是"每个语种独立的选题"**。翻译过来的内容在目标语种没有搜索需求匹配，等于把英文的选题硬塞进另一个市场。

**语种顺序建议**（按"一带一路受众 + 商业通用度 + 竞争强度"排）：

| 顺序 | 语种 | 理由 | 站点结构 |
| --- | --- | --- | --- |
| 1 | EN | 现有基线 | 根目录 `/` |
| 2 | **ES 西班牙语** | 拉美 + 西班牙，进口需求真实，英文竞争弱 | `/es/` |
| 3 | **PT 葡语** | 巴西是最大单一新兴市场之一 | `/pt/` |
| 4 | AR 阿拉伯语 | 中东采购需求强，但 RTL 版式要重构 | `/ar/` |
| 5 | RU 或 FR | 视 GSC 数据决定 | — |

**技术实现**：Astro 原生支持 i18n 路由（`i18n` 配置 + `[lang]` 目录）。**关键决策**：

- 用**子目录**而不是子域名（`landedmath.com/es/` 而不是 `es.landedmath.com`）——权重集中，且一次部署
- 每语种**独立 sitemap** 并在 GSC 里单独提交
- `hreflang` 标签必须成对且自指（这是多语言站点最常见的致命错误）

**成本**：每个语种约等于"再来一遍内容产线"，但**研究成本可以复用**（同一批一次文献），所以新增语种的边际成本约为首语的 50-60%。

### 5.2 YouTube 短视频（对应第 4 项）

**你描述的流程是对的**：每天选 1 个栏目 → 深度拆解成短视频 → 上传 YouTube → 拿到视频链接 → **回写到对应文章下**。

**这个闭环的价值在三处**：

1. **视频链接回写文章 = 文章停留时长上升**（嵌入视频是少数能显著提升 dwell time 的手段）
2. **文章描述里放视频、视频描述里放文章** = 双向导流
3. **`VideoObject` 结构化数据**让视频在 Google 搜索结果里独立出现（这是额外的 SERP 占位）

**实现要点**：

- 文章 frontmatter 已有 `youtube_id` 字段（v1.2 §5 定的），**但当前 schema 里没有**——需要补上并加 `YouTube.astro` 组件（用 `youtube-nocookie.com` + `loading="lazy"`，v1.2 §6 已定规范）
- 视频**不进 Git 仓库**（v1.2 §6），只存 ID
- 必须包含**真实录屏或你的声音**（v1.2 §6）——纯 AI 合成的视频对 E-E-A-T 是负分

**现实提醒**：视频是**第二条独立产线**（脚本、录制、剪辑、字幕、封面、上传），不是"顺手发"。v1.3 §15 特意把它排在基础设施之后。**建议 Y2 再正式启动，Y1 先跑通 3-5 条验证流程。**

### 5.3 播客音频（对应第 6 项）

**流程**：精选数据好的文章 → 每天 1 篇 → 转语音 → 自动分发到主流播客平台。

**平台**：Spotify / Apple Podcasts / YouTube Music / Amazon Music（通过一个 RSS feed 分发，**不用逐个平台上传**——这是播客生态的标准做法）。

**技术路径**：文章 → TTS 音频 → 托管（R2 或播客托管商）→ 生成播客 RSS → 提交一次到各平台。

**诚实提醒两点**：

1. **AI 合成语音在播客平台上口碑不佳**。听众能听出来。如果做，建议用你自己的声音（成本高但可信），或者明确定位为"文章朗读"而不是"播客节目"
2. **播客的价值是留存和品牌，不是流量获取**。别把它算进 UV 目标的主路径

### 5.4 AI 格式（对应第 5 项）—— 这里我要给你一个反直觉的结论

你说"文章除了 SEO 喜欢的格式外，还有 AI 喜欢的 llt 格式等 3 种格式"。**这个前提需要修正。**

我查证过 2026 年的实际情况：**`llms.txt` 对 AI 引用率没有可测量的影响**——30 万个域名的分析未发现相关性，采纳率约 10%，Google 的 John Mueller 表示没有 AI 系统在读它。

**AI 引擎实际读的东西，你已经在做了**：

| 你以为要做的 | 实际有效的 | 现状 |
| --- | --- | --- |
| `llms.txt` | ❌ 无可测量收益 | 未做 |
| — | **JSON-LD 结构化数据**（Article / FAQPage / Organization） | ✅ 已做 |
| — | **FAQ 结构与 80-150 词的答案** | ✅ 已做 |
| — | **段落级自包含**（RAG 按段落引用，44.2% 引用来自前 30% 文本） | ✅ AI Summary + Hook 承担 |
| — | **可验证的数据 + 具名来源** | ✅ 五元组 + `figures[]` |
| — | **作者实体与职位**（`jobTitle`） | ✅ 已做 |
| — | **RSS feed** | ✅ 已做 |
| — | **新鲜度信号**（`dateModified`） | ✅ 2026-10-07 已接通：`dateModified` 只读 `revisions`，而复查时钟（`reviewBy` + `tools/review-dates.mjs`）负责到期提醒。**注意两者必须分开**——把复查日期接进 `dateModified` 就是 Google 点过的刷日期行为 |

**建议的"3 种格式"应该是这样定义**（全部低成本或零成本）：

1. **HTML + JSON-LD**（给搜索引擎和 AI）—— 已有
2. **RSS / Atom**（给聚合器与 AI 爬虫）—— 已有
3. **`llms.txt` + `llms-full.txt`**（给 agent 的前向兼容基建）—— **顺手做，但不计入任何 KPI**

**唯一值得为此投入的是第 2 行和第 4 行**，而它们都已经在生产里了。**所以这一项的真实结论是：你已经做对了，不要把预算从内容挪到格式上。**

### 5.5 关键词挖掘测试（对应第 7 项）

**建议选 `sourcing` 栏目做测试**，理由：

- 现有 SERP 快照显示这个方向的**英文竞争最薄**（出口退税那篇的 SERP 几乎没有非官方英文竞品）
- 受众痛点具体（找厂、验厂、付款、单据），长尾词密度高
- 与你的"翻译层"定位最契合（把中国的一手要求讲给外面的买家）

**测试设计（8 周）**：

| 周 | 动作 |
| --- | --- |
| 1 | 用 GSC + Google Trends + Reddit（r/ecommerce、r/logistics）+ 问答站长尾，挖 100 个候选词 |
| 2 | 按"意图 × 竞争 × 商业价值"打分，选出 20 个 |
| 3-6 | 每周发 2 篇 sourcing 文章（共 8 篇），全部带 `target_keyword` |
| 7 | 跑 `pnpm qa:serp` 确认每篇的信息增量成立 |
| 8 | **对照**：sourcing 8 篇 vs 其他栏目同期的曝光/点击，得出结论 |

**回流机制（这是你要的"拿到数据后反馈优化"）**：

```
GSC query 数据
  → 有曝光无点击  → 改 title/description（最快见效）
  → 有曝光有排名但点击低 → 改 AI Summary（意图不匹配）
  → 30 天零曝光   → 先重跑闸门：通过 = 选题问题（退回选题池）；失败 = 闸门漏检（改规则）
  → 出现未瞄准的新 query → 直接进下周选题池
```

**这套回流机制 v1.3 §8 已经写好了，缺的只是"真的每周跑一次"。** 建议从 M3（有第一批数据时）开始，固定在每周一。

## 九、一句话总结

**五年 100 万 UV 的公式不是"多写"，是"写对 × 多语种 × 多渠道"。**

英文单语种的现实上限约 15-30 万月 UV；要破 100 万，必须在 Y2-Y3 把多语言和视频做成**独立的产线**，而不是附加动作。而这一切的前提是 Y1 先把"信息增量 + 数据可信"这套东西跑稳——因为那是唯一在 AI 时代还在增值的资产。

| PT | 500 | 22,500 |
| AR | 300 | 10,500 |
| **小计（搜索）** | **2,900** | **211,000** |
| × 视频 1.3 | | 274,000 |

## A.3 补这个缺口的四条路（必须选，不能不选）

| 路 | 做法 | 能补多少 | 代价 |
| --- | --- | --- | --- |
| **A. 提产量** | 每天 1 篇 → **每天 2 篇**（研究并行化，闸门不变） | +~35 万 | 需把研究 agent 并行度提到 4-6；你的每日审核时间从 0 升到约 30 分钟 |
| **B. 提单篇效能** | 选题从"纯长尾 B2B"扩到"中等搜索量词"（如 country-of-origin、HS code、de minimis 这类） | +~25 万 | **会稀释信息增量定位**——中等词竞争强，我们的成本测算优势变弱 |
| **C. 加语言** | 四语种 → **六语种**（+FR +DE） | +~15 万 | 边际收益递减，且 FR/DE 对华进口内容需求低于 ES/PT |
| **D. 视频做成真引擎** | YouTube 从"导流"变成"独立获客"（目标频道月 20-30 万播放） | +~20 万 | 这是第二条产线，Y2 起步到 Y4 才可能起量 |

**我的建议：A + D，不选 B。**

理由：**B 是唯一会破坏护城河的选项。** 这个站五年后唯一还在增值的资产是"我们自己算过、别人没算过的数字"。去抢中等搜索量词等于和几百个媒体拼发布速度，那是我们不擅长的战场。而 A（产量）和 D（视频）都是**在同一套能力上扩产能**，不是换打法。

**A + D 合计可补约 55 万，加上基线 36 万 ≈ 91 万。** 剩下的 9 万靠 C（加 FR 或 DE 之一）或让 ES/PT 的系数高于预期（西语区对"中国供应链"内容的搜索密度确实可能更高）。

## A.5 硬目标下的三个诚实提醒

**① 100 万是可达区间的上限，不是中位数。**
按上面的计划，中位数落点约 **90 万**，达标需要 ES/PT 的系数、视频的起量速度都不低于假设。**建议把"Y5 达到 60 万"设为保底、"100 万"设为冲刺**，而不是把 100 万当基准去做预算。

**② 最大的单一风险仍是 AI Overviews。**
R1 说 CTR 可能下降 61%。如果这件事在 Y2-Y3 全面发生，**上面的所有数字要整体下修 30-50%**，100 万就变成需要 7 年。这个风险你无法控制，只能对冲——而唯一的对冲是**邮件列表**（不可被算法剥夺）和**成本测算类内容**（AI 答不好，必须点进来看表）。

**③ 每天 2 篇 + 四语种 + 视频产线 ≈ 一个人做不完。**
即使有 agent 流水线，Y2 之后的工作量（每天 2 篇英文 + 翻译/本地化 + 视频脚本录制剪辑）现实上需要**至少 1 名兼职助手**，或者接受视频产线做得更慢。这一点建议在 Y2 开始时重新评估，而不是等到做不动。
