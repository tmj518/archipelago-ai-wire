# 信源清单（可清点的资产，不是口号）

> **这份文件的用途**：把"信源只认海关总署/商务部/统计局…"这句口号**变成一个可清点、可测试、会自动被读取的清单**。
>
> **建立于 2026-10-08。可达性是当天逐条实测的结果（不是猜的）。**
>
> **★ 这份文件是自动被读取的**——`daily-task.txt` 第一步就要求读它（见文末"如何被使用"）。

---

## 零、为什么有这份文件

**2026-10-08 用户在对话里直接指出**：

> "你的信息源是什么？哪几个部门和网站？中国这么大，一天找不到符合的信息，太假了吧。"

**这个质疑是对的。** 当时我把"找不到就写不出来"写进了 `初心与目标.md`——**而那是在为可能的产能不足预设借口。**

**正确的说法是"找不到就不要硬凑"，而不是"找不到"。**

**而更根本的问题**：**我从来没把信息源当成一个可清点的资产。** 所以这份文件的第一件事是**逐条实测可达性**。

### ★★ 海关总署这个问题要单独说

**实测（fetch 和 curl 都一样）**：

```
http://www.customs.gov.cn/                        412（连根路径也 412）
http://www.customs.gov.cn/customs/302249/...      412
http://www.customs.gov.cn/.../2799825/...         412
https://www.customs.gov.cn/                       SELF_SIGNED_CERT_IN_CHAIN
带 referer + cookie jar                            412
http://english.customs.gov.cn/                    200 ✅（40 KB）
```

**结论**：**中国海关总署整站有反爬网关（412 Precondition Failed），而不是某条路径的问题。**
**→ 所以进出口统计和税则要从英文站、或从财政部关税司、或从统计局替代。**

> **★ 这一条已经按用户定的规则处理**：**读不到的来源要写出来**。
> 所以它进了 `/sources/` 的"读不到"清单——**读者知道我们缺什么，比假装不缺更可信。**

### ★★ 2026-10-16 更正：海关总署**不是整站封锁，是反爬触发**

**上面把 `customs.gov.cn` 记为"412 整站"。实测发现那是【随出口路径变化】的，不是永久状态。**

```
2026-10-08  经本机代理   → 412（连根路径也 412）→ 当时结论"整站有反爬网关"
2026-10-16  直连（不带代理）→ 200 · 81,955 字节 · 正常文档
```

**★ 准确表述**：它按请求特征（出口 IP、头部、频率）**触发** 412，而不是整站拒绝。
**换个出口、放慢频率、带正常头部，它可能就给你。**

**★ 为什么这条值得更正**：**把"反爬触发"写成"整站封锁"，会让后来的人不再尝试，从而永久失去一个来源。**
`信源清单.md` 第九节自己写着"可达性会变"——**这一条就是它的实例，而 412/403 本就该隔期复测。**

**新增工具**：`node tools/check-source-reachability.mjs` —— 一次探测 15 个来源，区分
**可达 / 被拦（403·412·429）/ 挑战页（200 但字节过小）/ 抛错**，因为这四种要分别处理。
**它被设计成可以在 GitHub Actions 里跑**——用来回答"机房出口能否读到中国官方站"这个决定性问题。

### ★★ 2026-10-16 更正：英文站「海关公告」栏**可达但已停更**

**上面那张表原来把这栏标为"✅ 200 · 19 KB · 可直接引用为一次文献"。实测后证明后半句是错的。**

```
实测  http://english.customs.gov.cn/Legislation/Announcement   HTTP 200 · 19,454 字节
列表里最新的公告        GACC Announcement No.93 of 2023
可读公告                2023(93) · 2022(62) · 2021(54, 11) · 2020(84, 17, 16)
2024 / 2025 / 2026 年的公告   一条都没有
```

**→ 后果：`GACC 公告 2026 年第 74 号`（被 #27 引用）从英文站拿不到，中文站整站 412。两条路都断。**

> **★ 这是一个新形态，比 404 和 412 都隐蔽：**
> **404 是路径废了（换路径）；412 是反爬网关（换站）；**
> **"200 + 内容陈旧"是【页面活着、内容死了】——只看状态码和字节数会判它可达。**
> **它和 WTO 那个"200 但无内容"是同一类危险的两种变体：WTO 是空壳，这个是旧壳。**

**判别方法**：拿到列表页后，**取列表里最新条目的年份与今天比**。差一年以上就说明停更，
不能当作"今天的公告"来源。

**★ 而"统计发布日历"这条要标清楚**：**页面可达，但发布日期是 JS 渲染的**——
**`fetch` 拿到的是空壳。** 若要用它预排选题，需要一个能跑浏览器的抓取（我们已有 `check-mobile.mjs` 用的 headless 浏览器，可复用）。

**★ 为什么"发布日历"这个想法本身仍值得保留**：

> **我们的清单解决"有什么源"。发布日历解决"什么时候有新数据"。**
> **对"每天净新增 ≥1 篇"的节奏，后者让选题能预排，而不是当天现找。**
> **——所以它是"待实现（需 JS 渲染）"，不是"已可用"。**

```

## 五、★ 这些来源够不够"每天一篇"

**算术**：

```
可达来源                   23 个（加省级和替代入口约 30 个）
每个来源每天新增公告        1–20 条（政策密集期更多）
→ 每天可读的原始文献       几十到几百条

而我们每天只需要         1 个"有 ≥5 个可引数字 + 能算成本"的题
```

> **所以"一天找不到"在算术上不成立。** 真正的约束是**筛选成本**，不是来源数量。

**而筛选成本的正确解法不是"找不到就降低标准"，是**：
**按来源类型建索引**——下表就是索引的开端。

```

**规则的原话**：**"不管字数多少，内容完整度，满足用户搜索意图和文章有价值才是核心。"**

## 八、如何被使用（★ 自动化）

**`daily-task.txt` 第一步要求读这份文件**，所以它每天都会被读取，不靠人记。

**固定用法**：

```
第一步：选来源
  1. 读 信源清单.md 的"来源类型 → 能产出什么题"表
  2. 优先查本周被用得最少的来源类型
  3. 优先查省级和目的市场来源（信息增量最高）
  4. 海关总署相关数字走英文站或财政部关税司替代
```

**而每轮结束时要更新**：**新发现的入口、失效的入口、以及某来源实际产出了什么题。**

## 九、诚实的限制

| 限制 | 说明 |
| --- | --- |
| 只测了 37 个入口 | 不是全部。省级只测了浙江和广东 |
| 可达性会变 | 反爬策略和路径都会变，所以**失效的入口要定期重测** |
| **3 个"被墙"不一定是永久** | 403/202 可能只是当天策略，**要隔期复测** |
| 没测 API 的可用性 | 除 Federal Register 外，其他来源是否有 API 未核实 |
| 没测抓取速率限制 | 每天抓多少条会被限流，未知 |
