# 同行的成功，哪 10 个方面可以学习

**对象站点**：Landed Math（landedmath.com）—— 1 人、22 篇已发布、0 订阅者、暂无 analytics
**问题**：同行的成功，哪 10 个方面我们可以学习？
**日期**：2026-10-08
**素材来源**：`对标研究.md`（52 KB）、`行动清单_两份研究.md`
**与行动清单的关系**：行动清单回答"我们下一步做什么"；本文回答"他们为什么成功"。两者有重叠的地方我直接指过去，不重复写。
**方法**：所有关于同行的陈述都来自原研究实测抓取的页面，每条给 URL。**本轮我未能复测同行站点**——HEAD 请求全部无返回（本环境疑似无外网出口），因此引用前请自行点开确认；凡原研究标"未找到/存疑"的，本文沿用。详见文末"置信度"一节。

## 执行摘要

**这 10 条里只有一条值得排在第一，其他的都是它的配套：把每一个数据单元做成一个可被单独引用的 URL。** OWID 一篇 155 KB 的写作页里有 85 个 `<a>`、44 个站内链接，其中 11 个指向 grapher、9 个是彼此不同的图表 URL（`https://ourworldindata.org/what-impact-will-climate-change-have-on-malaria`）——它的图不是图片，是页面，每个有独立 canonical、独立元数据、独立下载与引用入口。这件事对 Landed Math 的价值之所以高于对任何别家，是因为需求侧已经准备好了：这个站的检索需求是数值型和定义型的（"7208 CBAM 每吨多少钱""entry date 和 ship date 的差别"），而单个数字恰恰是 AI 引擎最愿意直接引用、最容易被单独归因的形态。我们现在 195 条 figure 记录全部埋在正文里，0 条有 URL——**资产已存在，只差给它一个地址**。剩下的 9 条分三类：**机制类**（引用接口、邮件节奏、连接层、方法叙事——照抄机制，不抄体量）、**漏斗类**（先给后卖——两家都在用，且不需要规模）、以及 **3 条必须明确不学的**（团队规模叙事、日更频率、把可索引资产锁进会员墙）。第 10 条是"看起来该学其实只有他们能学"的典型：OWID 的 CC BY + 图表嵌入之所以能带来分发，是因为它有 14,000 个单元被别人搬走；对 22 篇的站，同一条路要反过来走——**先让内容可被抓、可被引，再谈被搬走**。

## 1. 把每一个数据单元做成独立可路由的 URL（★ 最高价值）

**具体做法**：OWID 的文章里不嵌图片，嵌的是指向图表页的链接。实测：一篇写作页 85 个 `<a>`，44 个站内，其中 11 个指向 grapher、9 个是不同图表 URL，还带视图参数（`?country=~PAK`、`?stackMode=relative`、`?tab=map&time=earliest..latest`）——`https://ourworldindata.org/what-impact-will-climate-change-have-on-malaria`。每个图表页有自己的 canonical、自己的元数据、自己的下载按钮和引用说明（`https://ourworldindata.org/faqs` 说明图表与自制数据为 CC BY）。

**机制**：一个数据单元拿到 URL，就同时获得了四件事：可以被单独索引（拿到长尾查询的落点）、可以被单独引用（引用方不必描述"他们某篇文章里的一个数"）、可以被单独更新（改一个数不牵动整篇）、可以被 AI 引擎当作**一个可归因的数据点**抓走。埋在正文里的表拿不到这四件事中的任何一件——它跟着文章的排名走，文章不排，表就不存在。OWID 的 9 个图表 URL 对一篇文章来说，等于把 1 个排名机会变成 10 个。

**在本站的等价物**：195 条 figure 记录（每条已经有 value + unit + period + named source + **retrieved date** 五元组，见 `https://landedmath.com/sources/`）生成 `/figure/<slug>/` 页面：值、单位、期间、来源、检索日期、用到它的全部文章、"这个数怎么用"一句话。然后文章正文里的数字改成链到该页。**这一步不需要新写任何内容——需要的是一次 schema、一次路由、一次回填。** OWID 的图表没有检索日期字段，我们的五元组比它严格，所以复刻它的结构我们是净赚。

**Effort**：中（一次性投入：schema + 路由 + 回填 + 正文改写）。之后每写一篇新文，figure 页面自动跟着产出，边际成本接近零。

**一人站适配**：**适合，而且是唯一一条"完全不依赖团队就能拿到最大额度收益"的动作。** 唯一注意：195 个页面里如果有一条 figure 只被 1 篇文章引用、也没有任何人会搜它，那它的价值低。判断标准是"这个数会不会有人单独搜/单独引"，不是"每个数都要有页"。

> 与行动清单重叠：这是行动清单第二梯队 2.1，本文不重复展开实施细节。

## 2. 给每篇文章一个机器可读的"引用接口"

**具体做法**：OWID 每篇文章带 7 个 Highwire Press 元标签——`citation_title`、`citation_author`、`citation_publication_date`、`citation_journal_title`、`citation_journal_abbrev`、`citation_fulltext_html_url`、`citation_fulltext_world_readable`，正文里另有两个锚点区块：`#article-citation`（人类可读引用串 + **BibTeX** 块）和 `#article-licence`（`https://ourworldindata.org/what-impact-will-climate-change-have-on-malaria`）。它的引用串里带的是一个**归档快照 URL**（`archive.ourworldindata.org/20261005-170829/...`），也就是"你引用的是我当时写的那一版"。

**机制**：这一层服务三类抓取者，而它们走的是不同的读法。学术数据库（Google Scholar 一类）读 `citation_*`；AI 抓取器读结构化程度最高的那一段；人类读者要一段能粘进文档的字符串。OWID 把三个入口都放在同一页，结果是**引用摩擦归零**——引用你的人不需要判断"该怎么标注来源"。摩擦越低，被引次数越高，而"被引"是这类站唯一不需要投放就能拿到的分发。

**在本站的等价物**：`BaseLayout` 加 `citation_title` / `citation_author` / `citation_publication_date` / `citation_journal_title`（写 `Landed Math`）/ `citation_fulltext_html_url`，加 `#article-citation` 与 `#article-licence` 两个锚点，许可证定 CC BY 4.0 写进 `/about/` 与 `/sources/`。我们已经有 `Article` / `Organization` / `Person` / `WebPage` JSON-LD，缺的只是 Highwire 这 7 个标签——**这与现有结构化数据不冲突，是并行的一层。**

**Effort**：极低（`BaseLayout` 约 10 行；许可声明是一段文字）。

**一人站适配**：**完全适合。** 这是本文里成本最低、又直接作用于"被 AI 引用"这个 target 的一条。注意它不会带来排名，它带来的是**被引用时的可归因性**——在没有订阅者、没有外链的阶段，被引是仅靠内容就能发生的分发。

> 与行动清单重叠：行动清单第一梯队 1.3 与第二梯队 2.3。

## 3. 把订阅入口接通，并给一个固定节奏（不是日更）

**具体做法**：Trivium 首页第一屏就是三个并列的邮件订阅表单（Trivium Tech Daily / Trivium China Daily / Net Zero Weekly，字段 First name / Last name / Email / Subscribe），免费日更 "One Thing from Beijing" 周一至周五，另有免费周更 "Net Zero Weekly"（`https://triviumchina.com/`、`https://triviumchina.com/one-thing-from-beijing/`）。它的产品级日更是收费层的核心卖点（`https://triviumchina.com/plans-pricing/`）。

**机制**：邮件在这门生意里的功能不是"分发内容"，是**制造回访**。搜索流量是一次性的：读者查到答案就走了，除非有一个外部理由把他拉回来。日更邮件提供的是这个理由——而且频率本身就是承诺的可信度信号（"周一至周五"意味着背后有人每天都在）。但要注意 Trivium 的频率之所以能成立，是因为它的免费层是 400–700 词的笔记，不是核算稿。

**在本站的等价物**：两件事，顺序不能反。**（a）先把 `mailto:` 换成真表单**（Buttondown / Kit / MailerLite 免费档即可）——首页现在自述 "Signup opens your mail client. Send the message and you are on the list — one click is not wired up yet"，也就是说订阅这个动作目前是**断的**，任何增长动作在此之前都没有意义。**（b）然后发每周一封**："本周唯一值得改报价的变动"，300 词 + 1 张表 + 1 个来源，直接用现有文章的 `The data point` 段落扩写。**每周，不是每天。**

**Effort**：极低（表单半天；每封邮件约 1 小时）。

**一人站适配**：**适合，但只能抄"固定"，不能抄"每日"。** 每天一封要求背后有一个轮班的团队；我们的每篇要读原始文书 + 做算术，日更会直接摧毁质量。**固定节奏是我们抄得起的部分，频率是他们规模才能承担的部分。**

> 与行动清单重叠：行动清单第一梯队 1.4 与第二梯队 2.4（前身）。这是全文与行动清单重叠度最高的一条。

## 4. 建立"连接层"，而不是继续加文章

**具体做法**：两家真正的护城河都不在单篇文章里，而在文章之间的连接组织。OWID 的 topic pages 是 126 个、每个是一页横向枢纽，`https://ourworldindata.org/trade-and-globalization` 实测 389 KB，结构是 H1 + 6 位作者 + 版本说明 + 页内 8 个分节的目录 + 三个并列 CTA + 收口列表；`https://ourworldindata.org/` 自述另有 29 个 data explorers。Trivium 是 84 个 `/channels/<product>-<topic>/` 页面把"产品 × 主题"交叉（`https://triviumchina.com/wp-sitemap-taxonomies-channels-1.xml`），同一个主题在四条产品线里各有一个 URL。

**机制**：连接层做的是**权重汇聚与查询面覆盖**。一个主题有枢纽页，簇内每篇文章都通过枢纽互相加权；同时枢纽页本身是"主题名"这种高意图查询的落点——它比任何单篇文章都更容易排上去，因为它覆盖的面更宽、被内链的次数更多。单篇文章是一根针，枢纽是一块磁铁。**缺了连接层，文章之间只是并列，不是集群。**

**在本站的等价物**：我们的约束是"不写更多文章"，那就把连接层建在已有资产上：`/instrument/<slug>/` 文书页（每个文书名一页，列出引用过它的全部 figure 与文章），加上 `/markets/` 已有的"按发布主体归类"规则（`https://landedmath.com/markets/`：Market is assigned per source, by the body that published it）。**这两个页面都是自动生成的，不消耗写作时间。**

**Effort**：中（生成逻辑，可从现有 `sources` / `figures` frontmatter 自动产出）。

**一人站适配**：**部分适合——这是本文里唯一一条明确"只做三分之一"的建议。** 我们的 22 篇文章即使全互链也形成不了 OWID 那种簇（126 个 topic 页背后是 508 篇文章）；一页只有 1–2 篇文章指向它时，枢纽页的价值有限。诚实的说法是：**连接层的机器今天就可以建（自动生成、成本低），但它的效力要等文章数到 40–60 篇才会显现。** 所以现在建的是"未来文章会自动落进去的架子"，不是"今天就能带来排名的资产"。如果只能做一件事，先做第 1 条。

> 与行动清单重叠：行动清单第二梯队 2.1 / 2.2 的产物。

## 5. 公开"我们怎么做"和"我们读不到什么"

**具体做法**：Trivium 有 `/our-process/` 讲它怎么处理信源（声明 "We rely principally on Chinese-language government documentation"，并**明确划出自己的边界**："Trivium is not a quant shop"）。OWID 有 `/faqs` 用专门条款区分"我们自制数据"（CC BY）与"第三方数据"（WHO/UN/World Bank，受各自许可约束）。两家都把"我们的方法与边界"当成一个独立的、可被链接的页面，而不是塞在页脚。

**机制**：方法与局限页面在两个方向上同时起作用。**对下游**，它回答了"凭什么信你"——而这个问题对匿名的小站比对有品牌的大站更致命；**对上游**，它是一篇可以被反复引用的元内容，因为它讲的是"某类工作的做法"，而不是某一条政策，所以它不会随政策到期而失效。Trivium 用一句 "not a quant shop" 换来了定位上的独占——它主动放弃量化，反而把量化这一块让给了别人（也就是我们）。

**在本站的等价物**：我们在这条上**已经站在比两家都好的位置，只是没把它讲出来**。`https://landedmath.com/sources/` 已经有 "What we tried to read and could not" 表格，把付费墙 403、PDF 无法解析、HTTP 202 空响应、定义页缺席四类失败公开列出，并写着 "A missing or uncertain figure is safer than a confident guess"；`https://landedmath.com/tracker/` 有按 30/90 天分级的复查队列（4 to re-check within 30 days / 12 within 90 days / 6 being watched）。缺的是**一篇叙事页**：谁在读哪份文书、一天读几份、读不到怎么处理、多久复查一次。素材已在 `/sources/` 与 `content.config.ts` 的字段注释里，**不需要新事实，只需要把它写成文。**

⚠️ **诚实边界**：这一条抄的是"讲方法"，不是"讲规模"。绝不写 "our analyst teams parse hundreds of sources" 这类话——那是 Trivium 有 25 个分析师才成立的说法。我们写的是"一个人怎么把一份联邦公报读成一个可复算的数"。

**Effort**：低（一篇 800–1,200 词，素材齐备）。

**一人站适配**：**适合，而且是本文里"投入产出比"仅次于第 1、2 条的一条。** 它把我们已有的独特资产（检索日期、读不到就写读不到、复查分级）从"结果统计"升级为"方法叙事"——而这两个竞争对手都没有对应机制（Trivium 未找到更正机制，OWID 只有版本快照而无"读不到"记录）。

> 与行动清单重叠：行动清单第二梯队 2.4。

## 6. "先给后卖"：样刊、试用、第一屏就给东西

**具体做法**：Trivium 在每个产品页顶部放 `Read a sample >` 按钮，有独立的 `/samples/` 页面，试用是 14 天（Neopol）/ 30 天（Markets、Tech）且**全部 no payment necessary**（`https://triviumchina.com/plans-pricing/`、`https://triviumchina.com/neopol/`）；首页第一屏三个表单是"先拿到邮箱"，不是"先收钱"。另有 `Compare Subscriptions` 把四条产品线的差异放在一页（`https://triviumchina.com/plans-pricing/` 导航内）。

**机制**：这条对付的是**最贵的那一步转化**——从"听说过"到"愿意试"。Trivium 卖的是 $188–1,345/年的判断类产品，而判断类产品的质量无法在购买前评估（不像实物可以先看规格）。所以它把评估成本降到零：不用付钱、不用留卡、先读一期。样品页还额外承担一个功能——**它是产品的说明书**，告诉读者"我们有哪些形态的内容、什么场景用哪个"，替代了它没有的术语表。

**在本站的等价物**：我们天然有样刊（22 篇已发布文章、`/tracker/`、`/calculator/`），缺的只是**把它们标成样刊**。最便宜的版本：在首页第一屏放一篇文章的 `The data point` 段落 + `/calculator/` 链接，而不是让 `Subscribe` 成为唯一动作。之后再做 `/samples/` 页与 landing 顶部的 `Read a sample`。

**Effort**：极低（首页一屏的改动，1 小时）。

**一人站适配**：**适合，且不依赖规模。** 注意它与我们"全站免费"的现状不冲突——现在我们没有付费层，所以"先给后卖"退化成"先给一个可核验的数，再谈订阅"。这个版本不需要付费墙、不需要收款方式、不需要会员系统，是当前阶段唯一能立刻执行的一条漏斗优化。

## 7. ❌ 不学：团队规模叙事

**他们怎么做**：Trivium 在 `https://triviumchina.com/one-thing-from-beijing/` 说 "Trivium has 25 analysts"，在 `https://triviumchina.com/our-services/` 说 "a 40-person team"（两页口径不同，原研究原样并列）；销售话术直接绑在这个数字上——"access to a 40-person team... for less than the cost of one full-time hire"。OWID 在 `https://ourworldindata.org/` 自述 14,092 charts / 126 topic pages / 29 data explorers / 508 articles，运营方是牛津的研究项目 + 英国注册慈善机构 Global Change Data Lab（Charity No. 1186433，`https://ourworldindata.org/funding`）。

**为什么不该抄**：规模叙事的真实作用**不是说服读者，是给采购方一个价格参照系**。Trivium 那句 "less than the cost of one full-time hire" 只在对着企业采购时成立——先建立一个"40 人"的锚，再说"比雇一个人便宜"，价格就显得合理；同时 25 个分析师也解释了日更的产能。我们的信任来源完全不同：**每条数字带检索日期、公式公开、读不到就写读不到**（`https://landedmath.com/sources/`）。去模仿"我们有多少人"，等于把一个我们本来就赢的维度换成一个我们必输的维度，还会稀释上面那条真正的差异。**该抄的是它们的机制，不是它们的体量。**

**一人站适配**：**明确不适合。** 这条不是"难做"，是"做了会反向伤害"。如果一定要在这一维度上发声，正确的方向是第 2 条与第 5 条（引用接口 + 方法叙事）——它们提供的可信度是**可核验型的**，而不是**体量型的**。

## 8. ❌ 不学：日更频率（学"固定节奏"，不学"每日"）

**他们怎么做**：Trivium 的免费 "One Thing from Beijing" 周一至周五更新（`https://triviumchina.com/one-thing-from-beijing/`），付费线另有产品级日更；全部更新建立在 25 人的分析团队之上。它的日更单篇约 400–700 词，结构固定（一句加粗判断 + `Some context:` / `This week's update:` / `Get smart:` / `Get smarter:` / `The upshot:`）。

**为什么不该抄**：**日更是一个产能承诺，不是内容策略。** 它能成立的前提是"每篇的边际劳动量 = 一个分析师半天"。我们的每篇要读原始文书（90 FR 55232、Regulation (EU) 2026/2108 这一级）+ 做算术 + 定复查日期，单篇边际劳动量是它的数倍。**在质量与频率之间，我们只能选质量——因为在 per-unit landed cost 这个领域，一个错的数比没有数更糟。** 而且日更的收益（复访习惯）在订阅者接近 0 时基本为零，此时它的成本却是全部。**该抄的是"固定"——读者知道下一封什么时候来；不该抄的是"每日"。**

**一人站适配**：**不适合。** 每周一封（第 3 条）是我们能长期维持的上限；日更会在两个月内变成"为了发而发"，直接命中 scaled content abuse。

## 9. ❌ 不学：把可索引资产锁进会员墙

**他们怎么做**：Trivium 建了 **1,177 个 `/sources/<entity>/` 信源页**（`https://triviumchina.com/wp-sitemap-taxonomies-sources-1.xml` 实测 1,177 个 `<loc>`），覆盖 新华社 / 国家发改委 / 国家统计局 / Qiushi / NPC 这类信源实体。但直接抓 `https://triviumchina.com/sources/nbs/` 返回的正文是登录表单（48 KB 页面，正文只有 "Welcome back! Log in to start reading deep intelligence"）。它的 `clients` taxonomy 同样在登录墙后。

**为什么不该抄**：这是本文里**最重要的一条"负面学习"**。Trivium 建了 1,177 个页面，Google 和 AI 引擎一个都读不到——**索引价值归零**。它之所以能这么干，是因为它的分发不靠搜索：邮件是入口（首页第一屏三个表单）、背后有销售团队处理企业定制需求。两个前提我们都不具备：我们是搜索与 AI 引用驱动的站，没有邮件列表、没有销售。**把可索引资产锁起来，等于自断供给。**

**在本站的等价物**：我们**已经在做对的版本**——全站公开、零登录、零付费墙。要做的是把它扩展到文书层：`/instrument/<slug>/` 文书页**必须公开**，不加"部分可见"、不加"登录看全文"。这条同时是对第 1、2、4 条的一个约束：**如果某个动作的代价是把页面放到墙后，就不要做那个动作。**

**一人站适配**：**结构上不适合，且比 Trivium 更不适合。** 一个靠邮件 + 销售驱动的站可以锁内容；一个 0 订阅者、0 销售的站锁内容就是把自己关掉。**公开不是我们的理想主义，是我们唯一的杠杆。**

## 10. ⚠️ 半学：OWID 的开放许可与"被别人搬走"（先做被抓，再想被搬）

**他们怎么做**：OWID 的图表与文章为 CC BY，图表页提供 PNG/SVG 下载并明确邀请 "embed our interactive charts in any website"（`https://ourworldindata.org/faqs`），并把翻译也做成外链激励（"翻译好了我们会链接你"）；站点自述其作品在 Wikipedia 一类站点上有 "hundreds of millions of views"（`https://ourworldindata.org/top-of-the-charts-2025`）。

**机制上要说清楚**：这条的分发不是"许可"本身带来的，而是**许可 + 一个可以被搬走的独立单元**共同带来的。别人能嵌入 OWID 的图，是因为那个图有独立的 URL 和一段 embed 代码；搬走一个单元的同时会带走 attribution 和一个回链。**没有可路由单元，CC BY 只是一句话，不会产生任何流量。**

**在本站的等价物**：两半分开处理。**该学的**是"给别人低摩擦的复用许可 + 可以被搬走的单元"——即第 1 条的 figure URL + 一条 CC BY 4.0 声明（"复用请署名并链回原文"）。**不该学的**是指望它带来流量：`?country=~PAK` 这种可嵌入交互图在 OWID 能传播，是因为它有 14,092 个图表、126 个主题页和一批媒体长期使用（`https://ourworldindata.org/`）。我们要做的是它的**倒数第二步**——先让内容可被抓取、可被归因（第 1、2 条），把"被搬走"当成结果而不是手段。**同时保留我们的独有形态：OWID 全页 0 个 `<table>`，两家都不是用表格做核算的；我们的 per-unit HTML 表格（22 KB 页面）在"多维数值核算"这个用途上比交互图更好用，不要为了模仿而删掉。**

**Effort**：许可声明极低（一段文字）；可嵌入单元 = 第 1 条的副产品，不额外投入。

**一人站适配**：**许可与可引用单元适合；指望"被搬走带来百万曝光"不适合。** 前者是我们能控的，后者是规模的结果。

## ★★ 每周五的稽核法（10 分钟，直接回应那个自陈的缺口）

**`daily-task.txt` 里写着**：

> **"机制清单里有 10 条，而实际执行的只有形态上的几条。"**

**稽核方法：每周五把十条逐条过一遍，每条只回答一个问题——**

> ### **「这一条，在最近 7 天的文章/页面里，能指到具体哪一处？」**

| 判定 | 动作 |
| --- | --- |
| **能指到** | 标 `已执行` + 记下位置（文件 / 行号 / URL） |
| **指不到** | 标 `未执行`，并**只挑一条**排进下周 |

**★ 纪律：一次只推进一条。十条同时推 = 十条都不动。**
**★ 关键在"可指认"这个判据——它比"感觉做了"严格得多，且 10 分钟能做完。**

**稽核表模板**：

| # | 机制 | 宣称已学？ | 最近 7 天可指认位置 | 判定 |
| --- | --- | --- | --- | --- |
| A1 | Email Whitelisting 页 | ☐ | | 已执行 / 未执行 |
| A2 | 存档日期 URL | ☐ | | |
| A3 | 定价页结构 | ☐ | | |
| … | … | | | |

**输出三样**：① 逐条核查表 ② 未执行的那几条各自缺什么（**具体，不是"还不够好"**）③ 建议下周只推进哪一条

**★ 为什么不能由执行者自己稽核**：**执行者无法稽核自己"哪条没执行"**——这是这套方法需要外部核验角色的原因。
